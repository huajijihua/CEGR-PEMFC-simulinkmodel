## 2. 用户确认的总目标

Route A 不是只服务 cEGR 的小型计算器，而是一个完整的、可扩展的燃料电池系统通用仿真平台。目标顺序为：

```text
完整燃料电池系统
    -> 进气控制、温度控制、水管理/水检测等基础系统能力
    -> 阳极、阴极、电堆、热管理和设备参数开放
    -> cEGR 作为系统扩展能力
    -> cEGR 对电性能和气路性能的研究与矩阵分析
    -> 可迁移、可追溯、可复用的面板与模型交付包
```

模型是核心，面板是用户操作和结果反馈接口，脚本只提供开发期接线检查、排错和必要审计。面板功能不能停留在少量边界条件输入和电堆宏观 KPI，但也不应被历史矩阵验证拖慢。

## 3. 运行环境与迁移边界

### 3.1 当前主要使用环境

当前主要由用户在已配置好的研究电脑上使用。MATLAB、Simulink、Simscape 以及模型所需的相关组件均视为本机已有前提。

### 3.2 迁移到其他电脑时必须列出的配置

迁移交付包必须提供一份依赖清单，至少包括：

| 类别 | 迁移要求 |
|---|---|
| MATLAB | 与当前模型兼容的 MATLAB 版本；具体版本和兼容性矩阵在交付前固定 |
| Simulink | 必须安装，用于加载、编译和运行 `.slx` |
| Simscape | 必须安装，用于物理网络和 Simscape logging |
| Fuel Cell 相关组件 | 必须具备模型所引用的 Fuel Cell/Gas Mixture 支持能力 |
| `FuelCell_lib` | 必须能合法获得并定位 MathWorks FuelCell 示例派生库 `FuelCell_lib.slx`，或提供等价的已验证库安装方式 |
| 工程文件 | 模型、面板、启动入口、参数脚本、接口注册表、结果提取器、验证脚本和必要说明文件 |
| MATLAB 许可 | 运行模型和相关工具箱所需的有效许可 |
| 操作系统 | 支持目标 MATLAB/Simulink 版本的系统环境 |

迁移说明不能只写“安装 MATLAB”。必须同时说明 MATLAB 版本、工具箱/组件、库文件、工程文件、启动方式和最小验证工况。

### 3.3 路径依赖要求

最终工具必须摆脱当前项目目录 `E:\agentwork_pemfc_cEGR_0519` 的固定路径依赖。允许工程内部存在相对目录结构，但禁止把该绝对路径或其他开发机绝对路径写入正式启动链、参数默认值和结果导出链。

目标行为：

1. 用户将整个 Route A 交付目录复制到任意合法目录。
2. 用户运行一键入口，不需要先手动切换到项目根目录。
3. 入口根据自身文件位置解析模型、脚本、参数和库定位信息。
4. 入口在启动前检查缺失文件、缺失函数、MATLAB 版本、工具箱和 FuelCell 库。
5. 检查失败时给出具体缺失项和修复建议，不进入半初始化状态。
6. 运行过程中不依赖 MATLAB 当前工作目录、用户 base workspace 残留变量或开发机特有的绝对路径。

`slprj/`、`.slxc` 和其他 Simulink 运行缓存不是迁移交付的必需源文件，可由目标电脑重新生成；它们不作为路径解耦的替代方案。

### 3.4 Agent 独立性

面板和模型运行不得依赖 Codex、Claude、OpenCode、MCP server 或其他 Agent 是否启动。Agent 只参与开发、审计和自动化操作，不是用户运行面板的运行时组件。

最终应支持：

- 从 MATLAB 命令窗口启动；
- 从一键 MATLAB 启动脚本启动；
- 在没有任何 Agent 进程运行时正常运行；
- 在 MATLAB 当前目录不是工程目录时正常运行。

没有 MATLAB 的电脑是否能够运行属于另一项 MATLAB Compiler/Runtime 部署课题，不纳入当前“解除路径依赖和 Agent 依赖”的承诺。当前交付目标仍是配套 MATLAB/Simulink 环境下的可迁移工具包。

## 4. 面板交付形态

### 4.1 当前开发主线

当前程序化 `.m` 面板足够支撑开发和 Git 审计，继续作为近期主文件。当前不把生成 `.mlapp` 作为功能开发前置条件。

### 4.2 一键入口

```text

```

一键入口负责路径解析、依赖检查、模型和脚本注册、参数环境检查及面板启动。它不应把参数常量、模型计算逻辑和 UI 回调混在一起。

功能、参数接口和结果布局稳定后，再评估将面板转存为 `.mlapp`。`.mlapp` 是后续维护和可视化编辑形式，不是当前运行能力的必要条件。

若最终同时保留 `.m` 和 `.mlapp`，必须明确一个主文件，避免两套实现长期漂移。优先保持一套核心逻辑，避免为了文件形式引入重复维护链。

## 5. 面板功能总体架构

“基础 / 高级 / 系统模型参数”作为配置层级，不能继续独自承担整个平台的信息架构。目标页面按系统域划分；第三层承接设备性能参数目录和后续已闭合的设备写入点：

1. 工况与电边界：Current、Power、Voltage、命令 profile、仿真时长。
2. 阴极进气与空气控制：空气控制模式、OER/目标质量流量/归一化空压机命令、入口压力、温度、组分和 RH。
3. 温度控制：堆温设定、冷却控制和热边界。
4. 水管理与水检测：加湿器、旁路、RH、出口水、分离水、凝结/分离状态和相关约束。
5. 阳极系统：供氢、阳极压力、H2 组分、加湿、回流和吹扫。
6. cEGR 系统：回流目标、控制模式、阀开度诊断、阀前后状态、管路状态和实际回流比。
7. 电堆与电化学：堆数量、活性面积、MEA 和电化学参数。
8. 设备参数：空压机、中冷器、加湿器、cEGR 阀/管路、分离器、腔体、冷却系统和散热器。
9. 控制器与求解器：PI/PID、执行器、限幅、solver、容差、最大步长和初态。
10. 结果与诊断：按电堆、阴极、cEGR、阳极、热管理和约束分区。
11. 矩阵研究：参数轴、基线对比、串行/并行执行、结果筛选和导出。

面板功能的扩展顺序必须服从“先确认模型接口和合法输入语义，再 UI 暴露”，不能只增加控件而不增加模型输入；模型是否收敛以实际面板运行结果为准，开发脚本不替代模型计算。

### 5.1 P1 当前操作闭环

P1 的交付重点是以下用户路径保持通顺：

```text
基础/高级控件
    -> simCase
    -> routeA_validate_case
    -> SimulationInput
    -> 当前正式 .slx / sim()
    -> 结果页、日志、失败分类和追溯信息
```

系统模型参数页作为设备目录：已闭合的设备写入点沿同一 registry/`SimulationInput` 链接入，未闭合项只读展示。

基础视图提供常用电边界、空气模式、RH/加湿器、cEGR 目标、堆温和仿真时长；高级视图补充入口边界、组分、阀模式、Voltage PI 和 solver 容差；系统模型参数视图集中显示电堆、空压机、加湿器、阀/管路、分离器和热管理等设备参数，并标注中文含义、开放状态和模型映射。下拉框负责互斥模式，复选框负责启停，数值框负责合法数值，灰显控件不作为当前控制源。阴极 RH 定义为加湿器出口/阴极入口 RH，温度参考沿用当前模型 `T_stack` 路径；新鲜空气源温度是独立的入口边界。空气模式 3 是归一化空压机执行命令（0-1），仍经过空压机图谱，不是直接给电堆气体。矩阵入口不属于 P1 用户操作路径。

### 5.2 新阶段三层责任

| 层级 | 必须负责的事情 | 不负责的事情 |
|---|---|---|
| 面板驱动层 | 收集用户输入、同步基础/高级值、处理模式互斥和开关启停、在运行前拒绝明显非法值、锁定运行中的输入、显示运行状态和失败信息 | 不直接改模型 block 参数，不复制模型计算或 KPI 计算，不把脚本通过当成模型收敛 |
| 统一装配层 | 将 UI 值整理为一个 `simCase`，由 `routeA_validate_case` 校验，再由 `routeA_panel_build_simulation_input` 生成唯一 `SimulationInput`；区分 runtime、compile-time 和只读项 | 不新增第二套 UI 入口，不绕过校验直接写模型，不隐藏参数覆盖关系 |
| 当前模型层 | 接收合法的 `SimulationInput`，执行当前正式 `.slx` 的物理网络和控制逻辑，发布可观测信号，返回 `SimulationOutput` 或可诊断的运行错误 | 不承诺面板未开放的 P2-P4 设备能力，不把未观测的液水、阳极或冷却状态伪装成已完成结果 |

P1 的主判断只有一个：用户填入合法值后，面板能否沿这三层链路启动当前模型，并把完成结果或结构化失败反馈回窗口。模型不收敛属于模型运行结果，面板需要清楚展示并保留错误栈，但不通过 UI 预设一个“必然收敛”的结论。

### 5.3 P1 面板自身功能需求

1. 电边界下拉框只允许 `Current / Power / Voltage` 之一，并同步命令单位；Voltage PI 只在 Voltage 模式可编辑。
2. 空气控制下拉框只允许目标质量流量、OER、空压机命令之一；目标质量流量是绝对 kg/s，OER 是无量纲相对目标，空压机命令是 `[0,1]` 归一化执行命令；只有当前控制源的输入框启用，其他值保留但不写成当前控制源。
3. 加湿器和 cEGR 复选框控制对应输入的启停；关闭 cEGR 时目标比例规范化为 0，关闭加湿器时 RH 保留但标记为本次不生效。
4. 基础/高级切换不能丢失高级值；高级中固定的 P1 选择项必须显示为固定或禁用，不能提供点击后无效的选项。
5. 点击运行后锁定输入和模式切换，状态区显示校验、装配、运行、提取结果等阶段；失败时同时显示失败分类、错误信息和追溯栈。
6. 结果区至少能显示电堆、阴极、cEGR、热/水、时序和诊断；不可观测项显示能力状态，不用 0 或空白冒充结果。阳极输入在当前高级区开放，阳极结果保持 status-only。
7. `清空结果` 只清理窗口结果，不修改当前输入和模型；完整版导出必须由用户明确选择，且保存后读回失败要回到诊断区。

### 5.4 P1 当前模型自身能力

当前模型已经作为 P1 活动能力的输入包括：

- Current、Power、Voltage 电边界和统一命令 profile；
- 阴极空气目标质量流量、OER、归一化空压机命令三种模式；
- 阴极入口压力/温度、出口背压、O2/H2O 组分、加湿器启用和 RH；
- 堆温设定、cEGR 启用/目标比例和 P1 阀模式；
- Voltage PI 参数、电流限幅，以及 `VariableStepAuto`、RelTol、AbsTol、MaxStep；
- 电堆 I/V/P、阴极流量/压力/温度/RH/组分、cEGR 实际比例/误差/回流量/阀状态和已注册的热/水观测。

当前模型明确不作为 P1 完整能力的内容包括：阳极结果闭环、冷却设备完整参数和结果、液水库存/输运/排液闭合、cEGR 直接阀面积主控、设备 map 和研究矩阵。按加速迭代口径，已存在统一 profile/SimulationInput 写入路径的阳极输入提前纳入当前面板；阳极结果仍按待确认状态显示。其余参数先通过全参数目录展示真实来源、范围和接入状态，只有完成写入点和应用动作闭合后再生成可编辑控件。

## 6. 参数开放策略

### 6.1 总原则

用户确认：原则上开放所有可以合理修改的设备参数，明显不可修改的基础物理常数除外。任何参数在面板开放前必须先经过接口、范围、编译、运行和物理响应验证，不能因为“模型工作区里存在变量”就直接暴露。

参数管理优先级为：

```text
鲁棒性 > 精简性 > 运行效率
```

精简指减少重复入口和维护链，不是减少研究所需的可调参数。

### 6.2 参数类别

每个参数至少分为以下类别：

| 类别 | 典型内容 | 面板行为 |
|---|---|---|
| 运行时控制参数 | 电边界、OER、入口条件、RH、目标温度、cEGR 目标 | 通过 `simCase`、profile 和 `SimulationInput` 传入，可直接运行 |
| 控制器参数 | 空气控制、温度控制、EGR PI、回流、吹扫、电压 PI | 修改前校验范围、饱和和控制模式，运行后检查响应 |
| 编译时设备参数 | 堆参数、管路尺寸、阀面积、腔体体积、分离器、冷却几何 | 应用后重新编译/初始化，并强制运行基线 smoke |
| 结构/表格参数 | 空压机 map、查表断点、曲线和矩阵 | 校验尺寸、单调性、单位和覆盖范围后应用 |
| 基础常数 | 明显属于物理常数且不应被研究工况改变的值 | 默认不作为普通控件；如确有研究需求，走工程参数入口 |

### 6.3 设备参数范围

目标上应逐步覆盖以下设备：

- 电堆和 MEA：cell 数、活性面积、流道、膜、GDL、交换电流、极限电流、传质和热参数；
- 空压机：转速断点、压比断点、流量 map、效率或相关可用参数；
- 中冷器：几何、流通面积、额定流量、压降、热边界和动态参数；
- 阴极加湿器：RH 设定、控制增益、旁路和管路参数；
- cEGR 阀和管路：最大/最小开口面积、执行器时间常数、管径、长度、粗糙度、体积和初始条件；
- 阴极尾气和分离器：腔体、压力、温度、压降、凝结/分离开关和 L2 参数；
- 阳极供氢、回流、吹扫和分离器；
- 冷却系统和散热器：层数、流程数、管径、散热器几何、翅片和换热参数。

### 6.4 参数注册表要求

为避免 UI 控件、模型变量和默认参数漂移，后续建立统一参数注册表。每个参数至少包含：

```text
canonicalName
displayName
domain
unit
defaultValue
minimum
maximum
source
modelWorkspaceVariable 或 block parameter
tunableClass
requiresCompile
validationLevel
riskLevel
description
```

参数默认值仍以 `platform_default` 为基线。研究工况、设备试验和外部案例应采用独立覆盖，不直接改写默认源文件。

当前面板采用“第三层全参数目录先行、可编辑控件分层开放”的加速策略：registry 中的 `active` 项进入统一 `simCase`/`SimulationInput` 链，`inventory` 项进入系统模型参数页的只读目录并显示中文含义、来源、单位、默认值、范围和接入状态；没有真实写入点的项不生成输入框。阳极十项输入已按该规则进入 active 层，阳极结果观测暂不因输入开放而自动升级。

### 6.5 参数开放前的验证门槛

每个新增开放参数至少需要：

1. 类型、单位、范围和缺省值验证；
2. 变量或 block parameter 的真实路径读回；
3. 编译时/运行时属性确认；
4. 默认值基线 smoke；
5. 合法扰动下无编译、DAE 或维度错误；
6. 结果变化方向或敏感性符合物理预期，或明确标记为尚无物理响应证据；
7. 非法值、维度错误、map 断点错误和互斥模式能够在仿真前拒止。

## 7. 基础燃料电池系统优先级

系统面板首先必须是完整燃料电池系统面板，然后才是 cEGR 研究面板。基础系统优先能力为：

### 7.1 进气控制

- 空气目标流量、OER 和归一化空压机命令三种控制语义；
- 阴极入口压力、温度、O2/H2O 组分和 RH；
- 空压机、中冷器和加湿器之间的输入/响应关系；
- 阴极出口背压和尾气流量；
- 入口到电堆气路的流量、压力、温度、组分和水状态。

### 7.2 温度控制

- 堆温设定；
- 冷却侧边界和冷却系统控制；
- 堆温、热流和热耗散结果；
- 温度控制对气体 RH、膜含水和电性能的影响。

### 7.3 水管理与水检测

- 阳极/阴极加湿器设定和旁路；
- 入口和出口 RH；
- 水分离量、凝结/分离状态和出口含水；
- 水管理相关的约束和异常诊断。

阳极和冷却结果可在第二阶段纳入完整结果面板，但系统接口不能因为面板尚未显示而被设计成不可扩展。

## 8. cEGR 控制语义

### 8.1 目标比例和阀面积的关系

当前模型的闭环语义是：

```text
目标 cEGR 比
    -> 实际回流比误差
    -> EGR 比例控制器
    -> 执行器动态
    -> 阀面积/阀命令限幅
    -> 实际 cEGR 流量和实际比例
```

因此目标比例和阀面积存在控制链耦合，但不是固定的一对一静态换算关系。相同阀面积在不同空压机流量、压力差、温度和气路状态下不一定产生相同的回流比例。

### 8.2 面板控制规则

一次计算只选择一个主控制入口；P1 只开放目标比例闭环，直接阀面积模式留作后续设备诊断：

1. **目标比例闭环模式**：用户设置目标 cEGR 比，面板和模型计算阀面积/阀命令；这是默认研究模式。
2. **直接阀面积模式**：用户设置阀面积或开度，用于设备特性、阀能力和开环诊断；模型计算实际回流比例。

不允许在同一模式下同时把目标比例和阀面积当作两个独立强制输入，否则会造成控制语义冲突或难以解释的覆盖关系。

### 8.3 cEGR 核心结果

即使目标比例闭环正常，也必须同时显示：

- 目标 cEGR 比；
- 实际 cEGR 比；
- 比例误差；
- cEGR 质量流量；
- 阀面积/开度命令；
- 限幅后的阀命令；
- 阀上游压力；
- 阀下游压力；
- 阀前后温度；
- 阀能力不足或控制饱和状态。

当阀面积不足导致实际回流量低于目标时，结果中必须把“目标未跟踪”和“阀/气路能力不足”区分开，不能只显示一个实际 cEGR 数值。

## 9. 结果展示与输出分级

### 9.1 结果内容原则

燃料电池系统的本质是气路、热管理和电化学耦合。电堆电压、电流和功率是气路进入电堆后的宏观结果，不能替代气路状态监测。

首要结果必须覆盖：

- 流量；
- 组分；
- 压力；
- 温度；
- 水/RH/分离水。

### 9.2 第一阶段结果范围

第一阶段优先显示电堆、阴极和 cEGR：

**电堆：**

- 电压、电流、功率；
- 堆温；
- 尾窗均值、波动、峰值和稳定性。

**阴极气路：**

- 入口和出口质量流量；
- 入口和出口压力；
- 入口和出口温度；
- 入口和出口 RH；
- O2、H2O、N2 组分；
- 出口水分离量和尾气状态。

**cEGR 气路：**

- 实际回流质量流量和比例；
- 阀前/阀后压力、温度和必要组分；
- 阀命令、阀面积、限幅和控制误差；
- cEGR 对阴极混合气和电堆性能的影响。

### 9.3 第二阶段结果范围

第二阶段纳入：

- 阳极入口/出口流量、压力、温度、RH 和 H2/N2/H2O 组分；
- 阳极回流和吹扫状态；
- 冷却侧流量、温度、热流和热耗散；
- 热管理约束和异常状态。

### 9.4 精简结果与完整结果

面板提供两种结果级别：

| 级别 | 默认行为 | 内容 |
|---|---|---|
| 精简版 | 只在面板内展示，不自动生成结果文件 | 关键电堆 KPI、实际 cEGR、阴极关键流量/压力/温度/组分/水指标、关键告警 |
| 完整版 | 用户明确选择后生成结果包 | 完整选定时序、参数快照、模型/脚本版本、工况、KPI、诊断、失败信息和可复现实验元数据 |

精简版不得为了展示而默认批量生成 CSV、MAT 或图像。完整版的文件格式、目录契约和保留信号清单在结果注册表确定后再冻结；初步方向是“人可读摘要 + 可恢复的详细数据 + 参数/工况元数据”。

## 10. 面板-模型双向迭代闭环

后续每个功能按以下闭环推进：

```text
研究问题
    -> 需要的控制量、设备参数和观测量
    -> 模型接口/物理机制缺口审查
    -> 模型或脚本最小修改
    -> 参数/信号注册
    -> 面板页面和交互实现
    -> 面板实际单工况运行
    -> 模型结果/失败反馈
    -> 必要时的开发期 smoke 和结果审计
    -> 更新规划和实施记录
```

面板暴露出的瓶颈必须反向推动模型和脚本优化，例如：

- 面板需要某个设备参数，但模型没有稳定的公开接口；
- 模型有信号，但没有规范日志名和单位；
- 目标 cEGR 和阀能力不足无法区分；
- 修改 compile-time 参数后没有自动编译和回归门禁；
- 结果无法追溯到参数集和模型版本。

这些问题不能通过继续增加 UI 控件掩盖，必须回到模型接口、参数层、日志链或面板错误反馈解决。验证脚本只在定位问题时使用，不是面板每次迭代的前置步骤。
