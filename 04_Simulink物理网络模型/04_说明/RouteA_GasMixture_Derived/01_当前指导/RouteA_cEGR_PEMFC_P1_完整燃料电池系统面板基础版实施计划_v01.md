## 1. 文件定位

本文件是 P1 阶段的具体实施计划，落实[面板-模型双向迭代规划](RouteA_cEGR_PEMFC_面板-模型双向迭代规划_v01.md)第 5 至第 10 节的约定。P0 只提供迁移、路径、注册表、model contract 和统一运行入口等准备能力，不是本阶段的核心交付。P1 从现有 `.m` 面板开始，正式进入面板与模型双向迭代主线。

本文件负责回答以下问题：

1. P1 具体实现哪些系统域、控件、模型接口和结果内容；
2. 每个控件开放前需要什么参数、编译、运行和物理响应证据；
3. 面板如何保持 Current/Power/Voltage、阴极进气、温度、水管理和 cEGR 的控制语义不冲突；
4. 哪些结果可以在精简版展示，哪些结果只能在完整版输出或标记为未解析；
5. 每个工作包如何通过面板直驱链、必要的开发期 smoke 和联合评审进入下一步。

P1 的状态由实际面板操作链、模型读回、运行结果和实施记录推进。本文保留 P1 基础接口和直驱链的范围边界；面板布局、输入严谨化、帮助说明和结果图像历史由 [P2 实施计划](RouteA_cEGR_PEMFC_P2_面板修复和操作性提升实施计划_v01.md) 承接。本文中的工作包和开发期 smoke 是实现辅助，不是历史验证任务清单；脚本不得自动宣布 P1 完成，也不因未重复旧矩阵而阻塞面板迭代。

### 1.2 阶段切换说明

用户确认 P1 已经完成较多基础工作，继续在 P1 堆叠历史验证不再作为当前推进方式。P1 保留“输入能够进入统一链、模型能够返回结果或失败”的基础能力；P2 专门处理窗口布局、输入单位/RH 温度语义、高级参数分类、帮助层和结果图像历史。P1 的 cEGR、阳极输入和系统模型参数目录不因阶段切换回退。

### 1.1 当前实施口径

1. P1 的唯一主路径是“基础/高级控件 -> `simCase` -> `routeA_validate_case` -> `SimulationInput` -> `sim()` -> 结果/失败反馈”；“系统模型参数”页承接设备参数目录和后续已闭合的设备写入点。
2. 控件只要已经接入这条路径并有合法范围、互斥关系和单位语义，就可以在面板上开放；模型是否收敛由实际运行结果判断，不由预先堆叠的脚本门替代。

4. P1 只保留 `cEGR=0` 和 `cEGR=0.3` 作为简单示例；不运行 cEGR 矩阵、长时历史工况或重复等价的旧验证。后续由用户直接在面板输入其他合法值。
5. 按用户确认加速面板迭代：阳极输入和全参数目录提前进入当前 P1 面板工作线。配置区由“基础 / 高级 / 系统模型参数”三层组成；已接入统一 profile/SimulationInput 的阳极输入可以作为活动输入；尚未确认模型写入点或响应的设备参数进入第三层 inventory 目录，不能伪装成有效编辑控件。

## 3. P1 目标、边界和非目标

### 3.1 P1 目标

P1 的目标是把现有 `RouteA_Panel_v01` 从“少量边界条件输入 + 电堆 KPI”提升为一个可运行的**完整燃料电池系统面板基础版**：

- 面板按系统域组织；“基础 / 高级 / 系统模型参数”三层只承担输入层级和设备目录分工，不再让基础/高级独自承担整个平台的信息架构；
- 先完成基础燃料电池系统能力，再把 cEGR 作为系统扩展接入；
- 电边界、阴极进气、温度控制和水管理具备统一输入、验证、运行和结果反馈链；
- 结果至少覆盖电堆、阴极气路、当前可验证的 cEGR 和水状态，而不是只显示电压、电流和功率；
- 所有 UI 输入都能回指 `simCase`、参数注册表、模型写入点和结果观测量；
- 通过同一个 `.slx`、同一个统一 runner 和同一个结果提取链支持单工况验证。

### 3.2 P1 必须保持的边界

1. 只有一个活动模型：`PEMFuelCellSystem_GasMixture_cEGR_RouteA_v01.slx`。
2. 活动运行继续使用 `cold_start_only`，显式 `LoadInitialState="off"`；历史热启动 bundle 不进入面板运行链。
3. 默认参数只来自 `platform_default`；旧台架、DQ60、workbook 和历史标定只能作为显式 `external_case` 背景。
4. 继续使用 `.m` 面板；不以 `.mlapp` 转换作为 P1 前置任务。
5. 面板只调用统一 `SimulationInput` 和结果提取链，不在 UI callback 中复制 plant 计算、KPI 计算或第二套参数默认值。
6. 未经接口和验证的物理块、inventory 参数、unresolved 观测量和假想的液水状态不得通过 UI 暴露。
7. P1 不把 cEGR 目标比例和阀面积当作两个同时强制的独立输入。
8. P1 的操作以面板单工况直驱为主：Current、Power、Voltage 等模式都沿同一运行链进入当前模型；不在本阶段扩展工况矩阵。
9. 若面板需要模型侧补接口或最小物理结构，允许另立模型变更项；必须先说明原因、修改范围、read-back 和单工况验证，不能由 UI 需求直接带入模型。

### 3.3 新阶段三层配合要求

| 层级 | P1 必须具备 | P1 明确不承担 |
|---|---|---|
| 面板驱动层 | 基础/高级输入收集、模式互斥、复选框启停、单位和合法范围提示、运行中锁定、结果/失败反馈 | 不直接写模型变量，不复制模型计算，不用隐藏脚本替代用户运行 |
| 统一装配层 | `simCase -> routeA_validate_case -> routeA_panel_build_simulation_input -> SimulationInput` 唯一装配链；明确 runtime/compile-time/readonly | 不允许 callback 绕过校验，不允许同一参数有第二个活动写入点 |
| 当前模型层 | 接收合法输入并执行正式 `.slx`，提供电堆/阴极/cEGR/热水可观测量或结构化运行错误 | 不把阳极完整闭环、冷却设备、液水库存闭合、直接阀面积主控和设备 map 伪装成 P1 能力 |

P1 的功能判断是：用户输入合法值后，点击运行可以启动当前模型；模型完成时窗口显示结果，模型失败时窗口显示失败分类、错误信息和追溯栈。收敛与否属于模型实际运行结果，面板只负责把结果如实呈现并保留下一步排错入口。

### 3.4 P1 面板自身功能需求

1. 电边界只能选择 `Current / Power / Voltage` 之一，命令单位随模式同步；Voltage PI 只在 Voltage 模式开放。
2. 空气模式只能选择目标质量流量、OER、空压机命令之一；前两者分别是绝对流量目标和相对氧过量比，模式 3 是 `[0,1]` 归一化空压机执行命令，非当前控制源输入框灰显且不作为本次控制源。
3. 加湿器和 cEGR 开关必须真正改变本次 `simCase` 语义；关闭 cEGR 时目标比例归零，关闭加湿器时 RH 保留但标记为不生效。
4. 基础/高级/系统模型参数切换只改变显示层级，不重置已输入值；P1 固定选择项显示为固定或禁用，不能保留无效选项。
5. 运行期间锁定输入和模式切换；运行日志显示校验、装配、运行和结果阶段；失败结果进入同一结果区，不只弹出临时对话框。
6. 结果页按电堆、阴极、cEGR、热/水、时序和诊断组织；不可观测项显示 `not_available` 或能力边界，不用 0 冒充反馈。
7. 矩阵、参数扫描和研究按钮不属于 P1 用户路径；清空结果不改输入，完整导出由用户明确触发。

### 3.5 当前模型能力清单

P1 当前可由面板驱动的模型输入为：Current/Power/Voltage、电流/功率/电压命令 profile、空气目标质量流量/OER/归一化空压机命令、阴极新鲜空气入口压力/温度、出口背压、O2/H2O、加湿器启用/RH、共享堆温/加湿温度、cEGR 启用/目标比例/P1 阀模式、Voltage PI 和 solver 容差/最大步长。

P1 当前可反馈的主要结果为：电堆 I/V/P 和堆温，阴极流量/压力/温度/RH/组分，cEGR 实际比例/误差/回流量/阀状态，以及已注册的热/水观测。阳极完整结果、冷却设备闭环、液水库存/输运/排液、cEGR 直接阀面积控制、设备 map 和矩阵研究列为后续阶段。

## 5. P1 面板功能架构

### 5.1 页面组织原则

P1 保留程序化 `.m` 面板，但将当前单一左右布局重组为系统域分区。推荐使用一个主窗口、一个系统域导航区和一个统一状态/结果区；不新增第二套面板实现。

“基础/高级”只在域内使用：

- 基础视图显示已验证、常用和运行时可调参数；
- 高级视图显示同一参数的诊断、控制器、solver 或编译属性；
- 高级视图不能绕过 registry、case validation 或 compile gate；
- 不为未解析信号和 inventory 参数创建可编辑控件。

### 5.2 P1 域清单和能力状态

| 域 | P1 面板内容 | 输入/输出状态 |
|---|---|---|
| 工况与电边界 | case ID、Current/Power/Voltage、标量/ profile、ramp、stop time | 主入口，必须可运行 |
| 阴极进气与空气控制 | 空气控制模式、OER/目标质量流量/空压机命令、入口压力/温度、O2/H2O、RH、出口背压 | P1 主功能，按运行时/编译时分开 |
| 温度控制 | 堆温设定、热边界状态、堆温反馈 | P1 主功能；冷却侧详细参数后置 |
| 水管理与水检测 | 加湿器启用、RH、入口/出口水状态、凝结/分离观测、L2 水能力状态 | P1 主功能；液水未闭合必须显式告警 |
| 阳极系统 | 源压力/温度、H2 分数、入口压力、RH、回流和吹扫输入；阳极结果能力状态 | 输入沿统一 profile 接入；结果信号仍按待确认状态展示 |
| cEGR 系统 | 目标比例闭环入口、目标/实际/误差、流量、阀命令与限幅、阀前后状态 | P1 最小诊断；直接阀面积模式在 P3 |
| 电堆与电化学 | 堆电压、电流、功率、堆温和尾窗稳定性 | P1 主结果 |
| 系统模型参数 | 第三层显示电堆、空压机、中冷器、加湿器、阀/管路、分离器、热管理等设备参数；同时保留完整平台目录、中文含义、来源、单位、默认值、开放状态和模型映射摘要 | active 映射沿统一链应用；inventory 只读展示，不生成无效按钮；后续逐项补齐真实设备写入点后再开放编辑 |
| 控制器与求解器 | 电压 PI、控制限幅、solver、容差、最大步长、初态策略 | P1 高级设置，均受校验 |
| 结果与诊断 | 精简 KPI、气路状态、cEGR 诊断、水能力、告警和失败分类 | P1 主结果 |
| 矩阵研究 | 参数轴、基线对比、串行/并行执行、结果筛选和导出 | P1 只预留入口，不运行矩阵；研究阶段另行实施 |

### 5.3 P1 控件与模型接口原则

每个控件必须建立以下可追溯链：

```text
控件 -> canonicalName -> simCase 字段 -> SimulationInput/Model Workspace 写入点
     -> 实际日志或 SimulationOutput 观测量 -> 结果域/告警 -> 验收证据
```

如果某个控件只能连接到文档名称、临时 workspace 变量或未读回的 block 参数，则该控件只能作为设计候选，不能进入 P1 活动面板。

## 6. 参数开放策略和 P1 白名单

### 6.1 参数分类

P1 沿用“鲁棒性 > 精简性 > 运行效率”的优先级，并在 registry 之上增加面板暴露级别：

| 面板暴露级别 | 含义 | P1 行为 |
|---|---|---|
| `basic` | 已验证的常用运行时参数 | 可在基础域直接编辑 |
| `advanced` | 已验证但具有控制、solver 或编译风险的参数 | 只在高级域编辑，应用前给出影响和门禁 |
| `readonly` | 结果、来源、状态或派生量 | 只读显示，不写回模型 |
| `inventory` | 已盘点但接口、范围或响应未闭合 | 不作为控件 |
| `unresolved` | 观测或模型接口尚未确认 | 不作为控件，不作为 KPI |

`active` 只表示脚本链可识别，不自动等于 `basic`。P1 必须在参数注册表中补充或派生 `panelExposure`、`applyAction`、`validationGate` 和 `unsupportedReason` 等面板元数据。

### 6.2 P1 首批开放白名单

首批白名单只包含以下经过 P0 接口基础覆盖、且能在 P1 逐项完成验证的参数：

| 域 | 参数 | 默认暴露 | 备注 |
|---|---|---|---|
| 电边界 | `electrical.mode`、Current/Power/Voltage profile、ramp、stop time | `basic` | 三种模式互斥，均映射同一 `I_cmd` |
| 电压控制 | `voltageController.Kp/Ki/currentMin/currentMax` | `advanced` | 仅 Voltage 模式生效，校验正值、限幅和 anti-windup |
| 阴极空气 | `airControlMode`、`targetOer`、`targetMdot_kg_s`、`directCommand` | `basic`/`advanced` | 目标流量/OER/空压机命令三种语义一次只选一种主入口；模式 3 为 `[0,1]` 归一化空压机命令 |
| 阴极边界 | 入口压力、入口温度、出口背压、加湿器启用和 RH | `basic`/`advanced` | 逐项确认真实写入点和物理响应 |
| 入口组分 | O2/H2O 组成 | `advanced` | 当前为编译时固定值；应用后必须重新编译和跑基线 smoke |
| 温度 | 堆温设定 | `basic` | 先验证设置到反馈的方向和热状态有限性 |
| 水管理 | 阴极/阳极加湿 RH、相关启用状态 | `basic`/`advanced` | 结果只能按已闭合的气相/相变证据解释 |
| cEGR | `enabled`、目标比例、当前有效控制模式 | `basic` | P1 默认目标比例闭环；不同时编辑阀面积 |
| solver | `VariableStepAuto`、RelTol、AbsTol、MaxStep | `advanced` | P1 当前 runner 固定 `VariableStepAuto`；仅开放容差和最大步长调整 |

以下参数在 P1 不进入可编辑白名单：阀面积几何、管径/长度/粗糙度、腔体体积、分离器效率、空压机 map、MEA/膜/GDL、冷却器几何和任何未验证的阳极/冷却参数。它们继续登记为 `inventory` 或 `unresolved`，由 P3-P5 工作包处理。

### 6.3 参数开放门

任何参数从 registry 进入面板前，至少完成接口和合法输入确认；以下条目是开发期检查顺序，按风险需要执行，不是每次面板迭代都要重复的历史验收包：

1. 明确 canonical name、显示名、单位、默认值、最小值、最大值、source 和适用范围；
2. 读回 Model Workspace 变量或 block parameter 的真实路径；
3. 确认运行时/编译时属性和应用动作；
4. 需要时用默认值执行最小 smoke；
5. 需要时用一个合法扰动定位 compile、DAE、维度或 NaN/Inf 错误；
6. 记录输出变化方向、敏感性或“当前无可观测响应”的证据；
7. 用非法值、互斥值、map 尺寸或单位错误验证仿真前拒止；
8. 将实际接口读回或面板运行反馈写入 P1 实施记录后，才允许将 `panelExposure` 从 `inventory`/候选升级为 `basic` 或 `advanced`。

## 7. 基础燃料电池系统实施优先级

P1 的执行顺序固定为“电边界 -> 阴极进气 -> 温度 -> 水管理 -> 结果 -> cEGR 诊断 -> 各功能独立单工况验证”。cEGR 目标比例可以作为系统扩展同时接入，但不能抢占基础燃料电池系统接口和结果闭环。工况矩阵、参数扫描和策略研究不属于 P1 验证。

### 7.1 电边界和电堆

- 统一 Current、Power、Voltage 三种用户语义到同一内部 `I_cmd`；
- 保证一次 case 只选择一个电边界类型；
- 在面板中显示命令、实际 I/V/P、堆温、尾窗均值、波动、峰值和稳定性；
- Voltage 模式显示 PI 参数、限幅和跟踪状态，不把 purge 周期响应误报成符号错误；
- P1 不复制三套 `.slx`、runner 或结果计算路径。

### 7.2 阴极进气和空气控制

- 支持空气控制模式 1=目标质量流量、2=目标 OER、3=归一化空压机执行命令；
- 明确新鲜空气入口压力/温度、O2/H2O 组成、加湿器出口/阴极入口 RH、共享加湿温度和出口背压的写入阶段；
- 显示入口/出口质量流量、压力、温度、RH、O2/H2O/N2 组分和出口水/尾气状态；
- 对编译时组分禁止在同一次仿真期间动态修改；
- 对空气控制模式变更执行互斥校验和最小响应测试。

### 7.3 温度控制

- 暴露堆温设定和已验证热边界；
- 结果显示堆温、温度尾窗和对气体 RH/电性能的影响；
- 冷却侧流量、热流和散热器详细参数不因 P1 控件需求提前伪造，留给 P4。

### 7.4 水管理与水检测

- 暴露加湿器启用、RH 和已验证的入口/出口水状态；
- 在结果区域显示气相水、RH、凝结/分离通量和可观测状态；
- 统一显示 `L2_not_closed`、`not observable`、`verified` 等能力状态；
- 在液水库存、输运、排液和分离效率没有闭合前，禁止显示“完整水收支通过”或给出分离效率数值；
- P1 必须先完成现有观测链审计，再决定是否需要最小必要模型接口修改；不以 UI 控件替代液水物理闭合。

## 8. cEGR 控制语义实施方案

### 8.1 P1 唯一主控制入口

P1 的默认 cEGR 控制模式为目标比例闭环：

```text
target cEGR ratio
    -> actual ratio error
    -> EGR controller
    -> actuator dynamics
    -> valve command/area saturation
    -> actual cEGR flow and ratio
```

P1 UI 中只允许选择一个主入口：

1. `target_ratio_closed_loop`：用户输入目标比例，模型计算阀命令/面积和实际回流；P1 默认且必须验证；
2. `direct_valve_area`：P1 不开放，留给 P3 的设备能力和开环诊断工作包。

`cegr.enabled=false` 时目标比例规范化为零；`cegr.enabled=true` 时目标比例必须在 registry 范围内。面板不能同时把目标比例和阀面积写入同一个 case。

### 8.2 P1 必须展示的 cEGR 结果

在现有日志和模型接口确认后，结果区域至少提供：

- 目标 cEGR 比；
- 实际 cEGR 比；
- 比例误差和跟踪状态；
- cEGR 质量流量；
- 阀面积/开度命令；
- 限幅后的阀命令或饱和状态；
- 阀上游和下游压力；
- 阀前后温度；
- 阀能力不足、压差不足或控制饱和告警；
- 对阴极混合气和电堆 I/V/P 的关联摘要。

某项状态尚未被模型真实发布时，必须显示“未解析/未验证”，不能用目标比例、阀面积或其他派生值冒充实测状态。

### 8.3 P1 cEGR 验收

P1 实际仿真只完成 `cEGR=0` 和 `cEGR=0.3` 两个简单面板 case，检查实际比例方向、质量流量、阀命令、阀前后压力和混合气组成。其他合法目标比例沿同一 target-ratio 输入链处理，不在 P1 重复运行或形成研究结论；目标未跟踪时仍需区分“控制器问题”和“阀/气路能力不足”。大范围目标、背压/湿度/温度/负载策略矩阵留给后续研究阶段，不作为当前 P2 面板修复的前置任务。

## 9. 结果展示与输出分级实施方案

### 9.1 统一结果对象

P1 不新增第二套 KPI 计算链。`routeA_panel_extract_results` 应继续复用统一 runner 的 assessment，并扩展为按域组织的结果对象，至少包含：

```text
resultContractVersion
case
parameterSnapshot
modelAndTopology
solverAndInitialization
status / passed / failureCategory
domains.stack
domains.cathode
domains.cegr
domains.thermal
domains.water
warnings / errors / observationReport
```

每个信号和 KPI 必须携带名称、单位、来源、时间范围、状态和是否允许作为验收依据的信息。`actual_cegr_ratio`、`waterCapability` 等字段不能只作为 UI 临时变量存在。

### 9.2 精简版

精简版是默认行为，只在面板内展示，不自动生成 MAT、CSV 或图像。至少包含：

- 电堆 I/V/P、堆温和尾窗稳定性；
- 阴极入口/出口流量、压力、温度、RH、O2/H2O/N2 组分；
- cEGR 目标/实际比例、流量、阀状态和控制误差；
- 水/RH/分离通量和 L2 能力状态；
- 关键告警、失败分类、模型 hash、参数层和 cold-start 状态。

### 9.3 完整版

完整版必须由用户明确选择，在结果 contract 和结果注册表通过后生成。P1 先完成最小可恢复结构，不把 P6 的最终迁移包提前冻结。完整版至少保留：

- 精简版全部摘要；
- 选定时序和原始/派生信号清单；
- 参数快照和 `simCase`；
- 模型文件、模型版本、拓扑 hash、solver、初始化策略；
- case 矩阵轴、执行方式和每个 case 的状态；
- warning/error、失败栈路径和观测量契约报告；
- 结果生成时间和可复现实验 metadata。

完整版输出必须由显式输出路径和输出级别触发。没有用户选择时，面板只保留内存结果和必要的精简摘要。

## 10. P1 具体实施工作包

### P1-W0：接口和能力矩阵冻结

**目的：** 将规划约定转成可执行的控件、参数、观测量和结果清单。

**工作项：**

1. 建立 P1 `panel capability matrix`，逐项记录域、控件、canonicalName、simCase 路径、写入点、输出、验证级别和后续阶段；
2. 为参数注册表增加面板暴露级别、应用动作和验证门字段；
3. 为观测注册表补齐 P1 所需阴极、cEGR、温度和水状态，区分 verified/optional/unresolved；
4. 定义结果 contract v01 的域结构和精简/完整级别；
5. 读回当前面板、模板、SimulationInput 和结果提取器，列出必须保留、重构、补缺和后置的代码路径。

**出口：** 每个 P1 控件和结果字段都有唯一来源；未解析项有明确 owner 和后续阶段；不存在同一参数的多个活动写入点。

### P1-W1：系统域面板壳和状态模型

**目的：** 将面板从“基础/高级”布局重组为系统域架构。

**工作项：**

1. 保留 `RouteA_Panel_v01.m` 为唯一主文件；
2. 增加系统域导航或分区，并将基础/高级降级为域内显隐级别；
3. 为每个域显示 `available`、`verified`、`inventory`、`unresolved` 或 `deferred` 状态；
4. 增加统一 case、运行状态、失败分类和结果级别状态区；
5. 所有控件通过统一收集函数生成 `simCase`，禁止 callback 直接写模型变量。

**开发期检查：** 通过 UI callback、默认值和 `simCase` 结构 smoke 检查接线；面板实际运行由用户直接触发，不把脚本结果当成用户工况验收。

### P1-W2：电边界、电堆和空气控制闭环

**目的：** 先完成基础系统的可运行控制链。

**工作项：**

1. 实现 Current、Power、Voltage 互斥选择和 profile 录入；
2. 复用统一 `routeA_panel_build_simulation_input` 和 electrical-boundary assessor；
3. 实现空气控制模式、OER/目标质量流量/归一化空压机命令互斥校验；
4. 实现入口压力/温度、O2/H2O、RH 和出口背压的分层应用；
5. 对 Voltage PI 的增益、限幅和 anti-windup 进行高级设置和拒止；
6. 结果中同时显示命令、反馈和电堆 KPI。

**开发期检查：** 可按需构造 Current/Power/Voltage、三种空气模式和非法输入样例，确认模式映射、互斥和仿真前拒止；不要求重复运行 600 s/3600 s 历史基线作为 P1 面板入口的前置条件。

### P1-W3：温度控制和水管理闭环

**目的：** 使面板不只关注电堆电性能，同时展示气路热状态和水状态。

**工作项：**

1. 接入堆温设定、温度反馈和热状态摘要；
2. 接入加湿器启用/RH、入口/出口 RH 和气相水/分离通量；
3. 读回并核对凝结/分离信号的单位、时间轴和来源；
4. 在结果层建立 L2 水能力状态，不把立即移除的凝结物写成液水库存；
5. 评估 L2 液水库存、运输、排液和分离效率闭合所需的最小模型接口；若需结构改动，先单独完成模型规格、model_edit、read-back 和 smoke，不直接由 UI 绕过。

**开发期检查：** 确认堆温、RH、加湿器和水观测已经写入结果域，并明确 `verified`、`gas-phase-only`、`not observable` 和 `L2_not_closed`；用户可直接在面板修改合法值观察模型反馈，不能据此宣称 full water balance 已闭合。

### P1-W4：cEGR 最小语义和诊断闭环

**目的：** 在不提前进入 P3 研究仪表板的前提下，把 cEGR 接入完整系统面板并保持控制语义正确。

**工作项：**

1. 将 P1 cEGR 主模式固定为目标比例闭环；
2. UI 只允许目标比例作为主输入，阀面积/开度作为结果和诊断；
3. 注册并显示实际比例、误差、质量流量、阀前后压力/温度、阀命令/限幅和能力不足状态；
4. 处理 `enabled=false` 与零目标的规范化；
5. 为未解析阀温度、饱和或能力状态建立显式缺口，不用派生字段冒充；
6. 保留 P3 直接阀面积入口的接口位置，但不在 P1 作为活动控制模式。

**开发期检查：** 只保留 `cEGR=0` 和 `cEGR=0.3` 两个简单样例，确认目标比例进入模型、实际比例/误差/回流量能返回窗口；其他合法目标值直接由用户面板输入，不再建立 P1 小回流矩阵。

### P1-W5：结果分级、诊断和独立单工况验证

**目的：** 将各面板功能的独立单工况结果变成可审计、可分级的面板输出；不在 P1 扩展为研究矩阵。

**工作项：**

1. 扩展统一结果对象为 stack/cathode/thermal/water/cegr 域结构；
2. 实现精简版默认显示和告警优先级；
3. 增加用户明确触发的完整版输出入口，路径和输出级别显式传入；
4. 保留 case、参数、solver、模型 hash、拓扑 hash、warning/error 和结果状态；
5. 为 Current、Power、Voltage、空气控制、温度/水管理和 cEGR 诊断分别定义必要的独立代表性单工况；
6. 不在 P1 增加组合矩阵、并行矩阵或参数扫描入口；后续研究阶段另立矩阵实施计划。

**开发期检查：** 需要时运行一个独立样例检查精简显示、显式完整版输出、失败分类和结果来源；不存在 P1 组合矩阵验收项，用户面板操作不依赖该脚本。

### P1-W6：回归、准入收口和文档同步

**目的：** 把 P1 的输入、运行和反馈链稳定到可以直接操作的面板-模型闭环。

**工作项：**

1. 处理面板实际操作中发现的控件、映射、错误反馈和布局问题；开发期按需运行最小 smoke，不建立重复历史验证包；
2. 对结构变化执行 `model_check` 和 model read-back；
3. 对每个新增观测量执行观测契约验证；
4. 回填实际模型 hash、KPI、结果文件、失败栈和未决风险；
5. 更新 P1 实施记录、路线图、面板规划状态和当前指导索引；
6. 若 P1 只完成代码而未满足出口门，状态写为“P1 实施中/验收未完成”，不得写成完成。

## 11. P1 工作包检查清单

P1-G0 至 P1-G5 是开发和交接检查项，不是必须逐项跑完的历史验收门。它们服务于发现“按钮无效、输入未传入模型、结果无法回写、失败没有分类”等工程问题；面板直驱链稳定后，用户可以直接通过窗口操作当前模型。P1-G6 保留为用户最终联合评审入口。

| 门 | 名称 | 必须证据 | 阻断条件 |
|---|---|---|---|
| P1-G0 | 规划追踪门 | §5-§9 追踪矩阵、能力矩阵、参数/观测/结果 contract | 任何活动控件无法回指模型接口或结果 |
| P1-G1 | 面板架构门 | 单一 `.m` 面板、域分区、基础/高级局部显隐、状态模型 | 出现第二套面板逻辑或 callback 直接改模型 |
| P1-G2 | 参数输入门 | 白名单、单位/范围/互斥校验、编译动作、非法值拒止 | inventory/unresolved 参数被开放 |
| P1-G3 | 基础系统直驱检查 | 面板输入能生成 `SimulationInput` 并启动当前模型；实际收敛由运行结果判断 | 控件未进入模型、运行异常无法回到窗口 |
| P1-G4 | 观测与结果检查 | 电堆/阴极/cEGR/热/水结果按可观测能力显示，失败也有结果对象 | 用宏观 I/V/P 掩盖缺失域，或错误只弹窗不留反馈 |
| P1-G5 | 追溯检查 | 需要时保留参数快照、solver、hash、失败栈和结果摘要 | 把矩阵数量或旧历史 case 数量当作 P1 门槛 |
| P1-G6 | 联合评审检查 | 代码、模型、说明、实施记录和验收摘要齐备，提交用户联合评审 | 未经用户确认就把 P1 写成最终交付 |

### 11.1 P1 交付判定

P1-G0 至 P1-G5 只构成可选的开发检查清单，不自动判定 P1 完成；P1-G6 是用户主导的联合评审入口。面板直驱链可用后，优先继续迭代 UI 和模型接口；液水闭合或关键观测有限时，按实际能力显示限制，不用矩阵数量替代功能交付判断。

阳极和冷却侧完整结果属于 P4，但 P1 交付必须在面板中诚实显示其能力状态，不能把 P4 尚未完成描述为完整系统结果已完成。

## 13. 后续阶段计划纪律

P1 之后的 P2、P3、P4、P5、P6 均必须在进入实施前，于 `01_当前指导/` 建立对应的具体实施计划文件。每份计划至少包含：

1. 对面板-模型双向迭代规划第 5 至第 10 节的追踪矩阵；
2. 目标、边界、非目标和与前一阶段的接口继承关系；
3. 参数、观测量、模型机制、面板控件和结果输出的工作包；
4. 每个工作包的代码/模型/说明产物、验证步骤和出口门；
5. P0/P1/P2 等准备工作与核心面板-模型功能的区分；
6. 未解析能力、液水闭合、阳极/冷却结果或设备参数开放等风险的明确 owner 和后续处理；
7. 对应的 `02_实施记录/` 增量记录入口。

没有对应当前指导实施计划时，只能进行只读盘点、接口设计和证据审计，不得直接把后续阶段功能写入模型或面板。
