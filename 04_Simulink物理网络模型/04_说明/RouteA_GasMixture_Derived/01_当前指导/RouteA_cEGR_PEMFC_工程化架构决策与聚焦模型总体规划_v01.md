# Route A cEGR-PEMFC 工程化架构决策与聚焦模型总体规划

文件类型：当前指导、架构决策和聚焦模型实施总规划  
日期：2026-08-14  
状态：用户确认研究逻辑和官方模块优先原则；2026-08-14 用户进一步确认将自增湿与双侧膜加湿拆为两个聚焦模型。本文件冻结实施顺序，不代表后续模型能力已经实现。

## 1. 事情的原委

阴极尾气循环不是一个单独的“增加回流支路”问题，而是一组必须分阶段裁决的工程系统问题：

1. 先选择一个可以制造、控制、保护和维护的系统拓扑；
2. 再研究该拓扑在哪些工况下有价值，以及它会带来哪些限制；
3. 最后与成熟的无 cEGR PEMFC 方案比较净收益、复杂度、风险和可靠性。

因此，项目不追求建立一个脱离工程决策的“通用 cEGR 模型”，而是建立一组具有统一接口和统一指标的架构聚焦模型。每个模型代表一个明确的工程假设，模型输出用于筛选和识别问题，不能在缺少参数和实验数据时直接替代硬件验证。

当前聚焦模型的原目标架构含义是：

> 被动式循环、普通 PEMFC 电堆、带外部膜加湿器、阴极出口经过液水分离边界后取气、回流至空压机入口，用于识别被动回流能力和空压机前气相冷凝风险。

当前模型正在向这个架构收敛，但最新模型读回显示当前 `CathodeWaterSeparator_FC` 只是 EGR 支路上的官方 `Flow Resistance (FC)`，排放支路从出口腔体另行取流；当前 `Pressure Relief Valve` 也位于排放支路，不等价于用户简图中的公共主干背压阀。因此当前实现仍是“阴极出口分支流阻代理”，尚未实现或证明“公共背压 -> 分离气相边界 -> 再分流”。用户已确认第一阶段先做两种阀门被动式配置：自增湿电堆和外部膜加湿电堆，具体裁决见[两种阀门被动式架构与控制边界裁决](RouteA_cEGR_PEMFC_两种阀门被动式架构与控制边界裁决_v01.md)。

## 2. 总体决策原则

### 2.1 统一研究接口，两个湿化物理模型

Route A 官方 Gas Mixture PEMFC 派生平台仍是系统主线。自增湿与外部双侧膜加湿具有不同的保守端口、跨膜质量传递和热传递拓扑。经用户确认，它们应作为两个独立的聚焦 `.slx`，不能通过同一物理链加元数据标签或一个 L2 流阻块表达。

后续优先采用以下形式：

- 两个受控派生的聚焦模型：`PEMFuelCellSystem_Cathode_cEGR_SelfHumidifying_v01.slx` 与 `PEMFuelCellSystem_Cathode_cEGR_ExternalMembraneHumidifier_v01.slx`；
- 一个正式聚焦 runner；
- 一套统一的 case、参数、观测和结果契约；
- 两个有唯一标识的架构模型；
- runner 每次 study 只运行一个模型，不混写结果；A/B 比较使用相同 case 契约和工况矩阵。

Route A 主模型、两个聚焦模型和历史资产的职责必须明确，不能形成无控制的第三套研究分支。

### 2.2 主动/被动按能量拓扑分类

主被动分类与控制方式分开：

| 分类 | 正式含义 | 备注 |
|---|---|---|
| 被动压力差式 | 不增加独立循环泵或风机，回流由系统压力差和支路阻力形成 | 可以使用阀门、节流件、背压控制和闭环控制 |
| 主动泵式 | 使用独立泵、风机或其他循环做功设备 | 必须计算额外功耗、温升、能力和失效降级 |
| 引射式 | 使用主气流压力能驱动回流，不增加独立循环泵 | 归入压力驱动被动式，但必须单独记录主气流压降和空压机功耗代价 |

阀门是否可控不决定主被动分类。控制器、阀门和空压机转速属于控制层；独立回流做功设备属于能量拓扑层。

### 2.3 官方物理模块优先

阴极气路、气体混合、压缩机、容腔、管路、流阻、阀、加湿器和燃料电池物理优先使用 Simscape/Simulink 官方模块和 MathWorks 官方案例。

MATLAB 脚本允许承担参数默认值、case 装配、`SimulationInput`、批量运行、结果读取和分析，但不得使用自建 `MATLAB Function` 替代质量守恒、压力降、组分混合、湿度、冷凝、压缩机或泵的核心物理。

如果官方模块不能覆盖某个部件，必须先登记能力缺口、输入输出和参数合同，不能用 MATLAB Function 隐藏缺口。现有历史 L2 MATLAB Function 代理必须标记为迁移或淘汰对象，不得作为新架构的正式物理依据。

### 2.4 用户确认的第一阶段两种配置

第一阶段先做两种阀门被动式、空压机入口回流配置，不进入独立循环泵或风机方案：

| 配置 | 架构标识 | 湿化方式 | 对照要求 |
|---|---|---|---|
| A | `Passive_SelfHumidifying_PostSeparatorGas_CompressorInlet` | 自增湿电堆，无外部膜加湿器 | 研究电堆产水、回流水蒸气、低负荷保湿和高负荷排水 |
| B | `Passive_ExternalMembraneHumidifier_PostSeparatorGas_CompressorInlet` | 外部膜加湿器 | 研究膜加湿器与 cEGR 的增湿、氧稀释、压降和协同 |

两种配置共享空压机前混合、空压机、中冷器、公共背压、分离气相边界、回流/排放分流、CEGR 阀、电负载和结果契约。第一阶段只改变电堆湿化方式。用户简图到当前 MATLAB 模型的详细映射、绿色设备控制边界和能力缺口见[两种阀门被动式架构与控制边界裁决](RouteA_cEGR_PEMFC_两种阀门被动式架构与控制边界裁决_v01.md)。

## 3. 架构决策矩阵

| 决策轴 | 候选方案 | 当前基线 | 实施顺序 |
|---|---|---|---|
| 循环驱动 | 被动压力差、主动泵、引射器 | 被动压力差 | 先与主动泵隔离比较，再研究引射器 |
| 电堆湿化 | 自增湿电堆、外部膜加湿器 | 两种配置并列作为第一阶段对象 | 当前单侧 L2 注水器不得直接称为外部膜加湿器 |
| 取气位置 | 分离后气相、分离器前湿气 | 分离后气相 | 分离器前仅作为液滴风险对照 |
| 接入位置 | 空压机入口、压缩机后/中冷器后、阴极入口侧 | 空压机入口 | 先完成空压机入口被动基线 |
| 控制方式 | 阀面积、压力、流量、空压机协同控制 | 阀和比例控制 | 在拓扑稳定后比较 |
| 热管理 | 无额外加热、保温、受控再热 | 无真实加热器 | 先做气相筛选，再建设备模型 |
| 液水处理 | 气相边界、理想分离边界、真实分离器 | 气相 L2 代理 | 获得参数和证据后再升级 |

目标基线的正式描述为：

> `Passive / ExternalHumidifier / PostSeparatorGas / CompressorInlet`

当前实现的临时架构标识为：

> `Passive / ExternalHumidifier / CathodeOutletBranchFlowProxy / CompressorInlet`

后续架构配置必须记录完整决策向量，不能只用“cEGR=0.3”或“主动/被动”作为模型名称。

## 4. 当前聚焦模型状态

### 4.1 已有能力

- 保留官方派生的阴极空气、压缩机入口混合、压缩机/容积、中冷器、加湿器、cEGR 阀、EGR 管和阴极背压网络；
- 保留官方 Stack/Core 和 MEA 气体/热接口；
- 采用固定堆温、简化阳极边界和气相 L2 水管理，缩小与当前问题无关的自由度；
- 已将阴极等效流阻接入官方 `Flow Resistance (FC)` 参数链；
- 已有被动回流控制、压力链、气相组分、露点、饱和度和冷凝率代理；
- 已有正式聚焦 runner、参数桥接、结果契约和冷态运行边界。
- 用户确认的两种第一阶段配置已冻结为自增湿电堆和外部膜加湿电堆；当前模型中的 `Cathode Humidifier` 仍是单侧 L2 注水接口，不等价于外部膜加湿器。

### 4.2 尚未闭合的能力

- 模型读回已确认 `CathodeWaterSeparator_FC` 是官方 `Flow Resistance (FC)`，只位于 EGR 支路；排放流量从 `CathodeOutletChamber` 的另一支路读回，因此当前结构尚未表达“分流前完成液水分离”；
- 当前水观测中的 `SeparatorOrCondensation` 是 L2 相态代理，不是液水库存、液滴输运、排液或分离效率模型；
- 当前 `r_mix` 是空压机入口混合基比例，不等于本规划规定的分流点回流率；
- 当前等效阴极流阻尚未用阴极入口/出口压差数据标定；
- 当前固定堆温不是加热器或换热器模型；
- 当前尚未闭合主动泵/引射器功耗和系统净功率；
- 当前结果仍属于 `behavior_verified_for_focused_scope`，不是工程方案验证。
- 用户简图中的公共背压阀位于分流前主干，但当前 `Pressure Relief Valve` 位于排放支路；公共背压、公共分离和再分流拓扑需要单独收口。
- 外部膜加湿器的干侧/湿侧换湿、传热和压降尚未在 `FuelCell` 四物种域中实现；自增湿模型也尚未从外部单侧注水接口物理移除并完成水账本验证。原单一模型中的 `MembraneHumidifierWet_L2_FC` 只是 `Flow Resistance (FC)` 历史接口试验，不属于任一正式湿化模型。

## 5. 统一接口和指标契约

### 5.1 拓扑接口

目标基线顺序为：

```text
阴极出口
-> 液水分离边界
-> 回流/排放分流
-> 回流支路
-> 空压机入口混合点
-> 空压机
-> 中冷器
-> 外部膜加湿器
-> 电堆阴极入口
```

“液水分离边界”在没有分离效率、允许含液率和排液参数前，只能表示分离后的气相边界和相关压损，不能宣称已经建立真实分离器。

### 5.2 回流率

在分流点定义主指标：

\[
r_{split}=\frac{\dot m_{return}}
{\dot m_{return}+\dot m_{exhaust}}
\]

其中分母是经过分离边界后的回流支路和排放支路总气体流量。该指标用于表达架构回流能力。

同时保留以下辅助指标：

\[
x_{comp,in}=\frac{\dot m_{return}}
{\dot m_{return}+\dot m_{fresh}}
\]

\[
r_{fresh}=\frac{\dot m_{return}}{\dot m_{fresh}}
\]

指标口径规定如下：

| 指标 | 作用 | 当前状态 |
|---|---|---|
| `r_split` | 分流点回流能力主指标 | 当前 runner 计算支路总质量流量代理；目标分离后位置尚未实现 |
| `r_split_dry` | 干基组分/氧稀释辅助指标 | 需补充支路组分观测；未具备前不得假算 |
| `x_comp_in` 或旧 `r_mix` | 空压机入口混合比例 | 当前已有，作为辅助指标保留 |
| `r_fresh` | 相对新鲜空气的回流比 | 当前已有，作为辅助指标保留 |

目标比例、执行器命令、`r_split`、`x_comp_in` 和 `r_fresh` 必须分开报告。

### 5.3 冷凝风险

当前采用气相集总、半定量判据：

\[
p_{H2O}=y_{H2O}p_{abs},\qquad
S=\frac{p_{H2O}}{p_{sat}(T)}
\]

必须观察空压机入口混合点、压缩机出口、中冷器后和加湿器入口等关键温压位置。主要输出为：

- 水蒸气分压；
- 露点温度；
- 露点裕度；
- 饱和度；
- 气相冷凝率代理；
- 潜在冷凝量或升温需求代理。

这些输出用于识别风险和防护方向，不代表液水库存、液滴携带、排液能力或空压机进液损伤。

## 6. 分阶段执行路线

### P0：架构和术语冻结

工作内容：

1. 固定当前基线的取气、分流、回流、混合、压缩、中冷和加湿顺序；
2. 固定被动、主动和引射式的能量拓扑定义；
3. 固定 `r_split`、`x_comp_in`、`r_fresh` 以及干/湿基口径；
4. 固定冷凝风险观察位置和判据；
5. 固定官方模块优先和禁止自建 MATLAB Function 的规则；
6. 建立架构配置登记表，禁止只用单一 cEGR 目标值命名架构。

出口门：所有架构、接口、指标和边界已经能够被独立读懂；没有新的物理模型修改请求进入 P1。

### P1：官方组件和实际拓扑审计

工作内容：

1. 对聚焦模型和官方案例进行 `model_overview`、`model_read` 和参数读回；
2. 已确认当前 EGR 流量传感器和 `CathodeWaterSeparator_FC` 位于出口分支路径，排放流量传感器位于另一出口支路；下一步需在官方模块范围内重构或明确目标分离后分流边界；
3. 确认压缩机、中冷器、膜加湿器和电堆入口的真实顺序；
4. 建立官方组件来源表和气体域兼容性表；
5. 识别所有承担核心物理的 MATLAB Function 或不透明代理；
6. 建立能力缺口清单，不用未验证的模块名称代替物理证据。

出口门：每个核心物理模块都有来源、端口语义、参数写入点和适用边界；当前分离器缺口和目标拓扑改造方案得到明确结论。

### P2：当前被动式基线收敛

工作内容：

1. 将当前模型同时标记为目标架构 `Passive / ExternalHumidifier / PostSeparatorGas / CompressorInlet` 和当前实现 `Passive / ExternalHumidifier / CathodeOutletBranchFlowProxy / CompressorInlet`；
2. 在官方模块范围内明确“分离后气相边界”和回流/排放分流的实现方式；若不能证明真实分离效率，则将其降级为气相边界和压损代理；
3. 将 `r_split` 设为结果主指标，保留旧 `r_mix` 和 `r_fresh` 作为辅助指标；
4. 由回流和排放支路的实际流量计算 `r_split`；
5. 增加支路总流量和流量闭合状态；
6. 继续使用官方气体、阀、管路、容腔和流阻模块；
7. 不新增真实加热器、真实分离器或主动泵，除非相应参数合同已具备；
8. 对现有 MATLAB Function 水代理建立替换或淘汰路径。

出口门：模型读回证明目标拓扑或明确代理边界，`r_split` 的物理位置和状态有明确标识，零回流和小回流行为通过，且没有新建的自定义物理函数。

### P3：基线分层验证

验证顺序：

1. 结构和连接检查；
2. 冷态初始化和编译；
3. `cEGR=0` 无回流基线；
4. 小回流方向验证；
5. 中等回流和背压验证；
6. 回流/排放质量闭合；
7. 气体组分、氧稀释和湿度方向；
8. 露点和冷凝风险筛选；
9. 求解器和参数敏感性。

必须区分：已实现、结构读回、已执行、聚焦范围行为验证和工程验证。没有实验或独立参数证据时，不把结果提升为工程验证。

### P4：被动式适用场景矩阵

优先研究：

- 低负荷、怠速和低流量；
- 额定附近和高负荷；
- 冷环境、常温和高温环境；
- 低湿和高湿环境；
- 不同阴极背压；
- 不同空气 OER、空压机流量和外部加湿器设定；
- 启动、负荷阶跃和负荷斜坡；
- 回流阀限幅、控制失效和 cEGR 条件切除。

输出被动式的可行域、压力裕度、冷凝风险区和控制失败边界，不只输出一个最优比例。

### P5：单轴对照架构

第一对照只改变循环驱动：

> 主动泵 + 普通电堆 + 分离后取气 + 空压机入口回流。

其他条件保持一致，并增加泵流量、压升、功率、温升和失效降级指标。没有泵参数合同时，主动方案只能作为显式假设扫描，不能称为工程方案。

第二对照只改变电堆湿化：

> 被动式 + 自增湿电堆 + 相同取气和接入位置。

第三对照再研究取气和接入位置变化。控制策略比较放在拓扑稳定之后。

### P6：工程问题和使用场景归纳

每个架构统一输出以下风险：

- 回流能力和压力裕度；
- 阀或泵能力边界；
- 空压机工作点变化；
- 入口露点和冷凝风险；
- 氧稀释和电堆性能变化；
- 外部加湿器负荷；
- 控制稳定性和失效降级；
- 额外压降、功耗、组件和耐久风险。

### P7：与成熟方案比较

第一比较基线为：普通 PEMFC + 外部膜加湿器 + 无 cEGR 的常规阴极供气方案。

统一比较：

- 堆功率、电压和净功率；
- 空压机、泵和加湿器功耗；
- 水源和热负荷；
- 回流能力和工作包线；
- 冷凝和液水防护需求；
- 控制复杂度、组件数量和故障降级；
- 成本、可靠性和耐久性证据。

模型直接支持的指标与需要实验、供应商或 `external_case` 证据的指标必须分开。

### P8：实验标定和工程闭合

标定顺序：

1. 阴极入口/出口等效流阻；
2. 回流阀和回流管路压损；
3. 温度、露点和冷凝风险边界；
4. 分离效率、允许含液率和排液能力；
5. 泵、引射器和空压机功耗；
6. 可靠性、故障和耐久参数。

实验数据进入 `external_case` 或经批准的 `platform_default` 参数链，不允许未经标注地覆盖默认值。

## 7. 统一验证门

| 门 | 目的 | 最低证据 |
|---|---|---|
| Gate 0 | 架构语义冻结 | 拓扑、指标、模块来源和边界契约 |

| Gate 6 | 工程结论 | 参数/实验/供应商证据与模型结果闭合 |

任何架构没有通过前一门，不进入后一门。不得用增加模型复杂度、放宽 solver 或增加 MATLAB Function 绕过失败门。
