# Route A cEGR-PEMFC P2 面板修复和操作性提升实施计划

文件类型：阶段实施计划（面板-模型双向迭代主线）<br>
日期：2026-07-30<br>
版本：v01<br>
状态：P2 实施中；以面板操作闭环、输入语义和结果反馈可用为主，不重复历史验证工况<br>
适用模型：`PEMFuelCellSystem_GasMixture_cEGR_RouteA_v01.slx`

## 1. 阶段定位

P1 已经形成单文件面板、基础/高级/系统模型参数三层配置、统一 `simCase`/`SimulationInput` 链和结果契约初版。继续在 P1 中堆叠历史验证会拖慢面板迭代，因此当前阶段切换为 P2：面板修复和操作性提升。

P2 的主判断仍然只有一个：用户能否在一个集中窗口中选择模式、勾选开关、输入带单位且合法的参数，点击运行后由当前正式模型计算，并把完成结果或结构化失败反馈回同一窗口。模型是否收敛由实际运行结果决定，不用预先堆叠验证工况替代这条闭环。

## 2. 继承边界

1. 继续使用单一 `RouteA_Panel_v01.m`、单一正式 `.slx`、`platform_default` 参数链和现有 runner。
2. P2 不修改正式模型结构；只有当面板操作暴露出明确的模型接口错误时，才另立最小模型修复项，并执行 read-back、`model_check` 和必要短 smoke。
3. 所有可运行输入仍必须经过 `UI -> simCase -> routeA_validate_case -> SimulationInput`；callback 不直接写模型。
4. 不重复运行 P1 已完成或等价的 Current/Power/Voltage、cEGR=0/0.3 和历史矩阵；只做 UI 状态、回读和必要的短交互检查。
5. 系统模型参数页继续展示全参数目录。没有真实写入点、范围或物理响应闭环的 `inventory` 参数保持只读，不生成无效输入框。
6. P1 的 cEGR、阳极输入、气相水和当前结果能力继续沿用；P2 不把未观测的阳极、冷却或液水状态宣称为完整闭环。

## 3. P2 目标和非目标

### 3.1 目标

- 去掉左侧系统域导航占位，让配置区和结果区获得稳定空间；
- 将配置区明确分为“基础 / 高级 / 系统模型参数 / 帮助”四层，切换不丢值、不改变模型输入语义；
- 统一显示单位、范围和控制源，特别是 RH 必须与对应气体温度一起表达；
- 将高级参数按电边界、电压控制、阴极气路与湿度、cEGR、热/求解器、阳极扩展分组；
- 将“时序”改为“结果图像”，按电流-时间、功率-时间、电压-时间独立切换；
- 多次面板运行保留带 `caseId` 的图像历史，并提供独立的清空图像按钮；
- 运行失败、无效输入、灰显控件和结果清空行为保持可理解、可追溯、不弹出无上下文的假成功。

### 3.2 非目标

- 不在 P2 开放未经接口闭合的设备参数写入；
- 不在 P2 增加 cEGR 研究矩阵、并行矩阵或批量研究入口；
- 不在 P2 修改电堆、空压机、阀门、液水或冷却物理结构；
- 不在 P2 把 `.m` 面板迁移为 `.mlapp`；
- 不把 UI read-back、代码静态检查或历史仿真结果写成当前模型重新收敛证据。

## 4. 面板信息架构

### 4.1 配置层

| 层 | 责任 | P2 操作要求 |
|---|---|---|
| 基础 | 常用工况和控制输入 | Current/Power/Voltage、空气控制、入口/出口边界、RH+温度、cEGR、堆温和时长；非当前控制源灰显 |
| 高级 | 分组的控制器、气路、solver 和阳极输入 | 每组有清楚标题；固定/不支持的选项只读或禁用；切换不重置值 |
| 系统模型参数 | 完整设备参数目录 | 显示中文含义、单位、默认值、开放状态、应用方式和模型映射；inventory 只读 |
| 帮助 | 输入指导和控制原理 | 解释电边界、空气模式、RH/温度、cEGR 主入口、参数生效链和常见失败含义 |

### 4.2 结果层

结果页保留总览、阴极、cEGR、热/水和追溯/诊断。原“时序”页改名为“结果图像”，内部设置三个互斥图像选项：

1. 电流-时间；
2. 功率-时间；
3. 电压-时间。

每次完成的独立运行追加一组历史曲线，图例使用 `caseId`；重复 `caseId` 时追加运行序号但保留原始 `caseId`。清空结果表不自动删除图像历史，图像由“清空图像”单独控制。

## 5. P2 工作包

### P2-W0：阶段和交互契约同步

更新 P1 状态、总规划、收敛路线图、当前指导 README、平台测试计划和 P2 实施记录入口。固定四层配置、结果图像历史、输入单位/RH 温度语义和不重复旧验证的开发口径。

出口：所有当前指导文件对 P2/P3/P4/P5/P6 的阶段含义一致；没有把 P2 误写成 cEGR 研究阶段。

### P2-W1：面板壳和布局修复

1. 隐藏并移除左侧系统域导航对布局的占位影响；
2. 采用“左侧配置、右侧结果”的稳定两栏布局，保留配置滚动和结果滚动；
3. 增加帮助层；
4. 配置层按钮统一互斥，切换基础/高级/系统模型参数/帮助不丢失已填值；
5. 保留后续 P3-P6 扩展空间，不把运行按钮埋入滚动内容底部。

出口：窗口在常用桌面尺寸下不出现控件重叠；左侧导航不再可见或影响可用宽度；最新版窗口默认保持打开。

### P2-W2：参数输入严谨化和高级分组

1. 所有基础/高级数值输入补齐单位或无量纲说明；
2. RH 明确为 `0-1` 相对值，定义为加湿器出口/阴极入口 RH；温度参考使用 `thermal.stackTemperatureSet_C` 对应的模型 `T_stack` 路径，基础页显示为“加湿温度”，高级页另行保留新鲜空气源温度；
3. 空气模式、cEGR、加湿器和 Voltage PI 继续使用下拉框/复选框/灰显互斥逻辑；
4. 高级页按电边界与 PI、阴极气路与湿度、cEGR、热/求解器、阳极扩展分组；空气模式 3 明确标为归一化空压机执行命令，不伪装成 kg/s 或 OER；
5. 帮助页解释 Current/Power/Voltage 的控制原理：Current 直接给电流边界，Power 由功率命令换算电流，Voltage 由电压 PI 调整电流；
6. 输入链继续由统一收集和验证函数处理，禁用值不作为当前控制源写入。

出口：用户能从标签、单位、帮助和灰显状态判断“填什么、何时生效、模型接收什么”；不存在点击后不改变输入或模型语义的选项。

### P2-W3：结果图像和历史管理

1. 将 Trace tab 改为结果图像；
2. 三个图像选项只切换显示指标，不重新运行模型；
3. 每次完成运行将电流、功率、电压 timeseries 和 `caseId` 追加到内存历史；
4. 图例、标题、纵轴单位随选项更新；
5. 增加独立“清空图像”按钮；
6. 失败运行不伪造曲线，也不删除已有成功历史。

出口：连续运行多个 case 后可以在三个图像视图中回看历史，caseId 可追溯；清空图像不误删参数和结果表。

### P2-W4：操作错误和反馈修复

1. 运行期间锁定输入和模式层，结果图像查看/清空行为不产生新的模型写入；
2. 失败结果仍进入结构化结果对象和诊断页；
3. 清空结果、清空图像、导出完整结果三个动作边界明确；
4. 不支持或尚未闭合的设备参数继续显示状态，不生成“看起来可填但无效”的按钮；
5. 对重复 caseId、空结果和无有效曲线状态给出明确显示。

出口：面板状态变化不依赖 MATLAB 弹窗才能理解；没有残留旧曲线冒充当前结果、清空范围不明或输入偷偷回退的问题。

### P2-W5：UI 读回和用户联合评审准备

只做代码分析器、`git diff --check`、面板创建/控件状态/布局/模式切换/图像历史的 MATLAB read-back。需要模型运行时由用户在保持打开的最新窗口中直接操作；不以本工作包重新跑旧工况作为出口。

出口：P2 代码、说明和当前窗口一致，剩余问题进入 P2 实施记录和下一轮修复清单，由用户进行面板联合评审。

## 6. P2 检查门

| 门 | 检查内容 | 阻断条件 |

## 7. 设计建议

P2 后续迭代建议继续保持三点：

- 在运行按钮附近显示“当前生效控制源”摘要，降低基础/高级切换后的误操作；
- 对 compile-time 或 inventory 参数在目录中继续显示“应用方式/模型映射”，只有闭合后才升级为可编辑控件；
- 图像历史先保留在当前 MATLAB 会话内，等结果契约和用户查看习惯稳定后，再决定是否将图像历史纳入 full export。
