# 实施记录

本目录只记录实际发生过的工作、读回证据、验证结果和未解决风险，不承载新的模型设计决策。

## 文件分类与更新规则

本项目说明文件分为两类，更新方式不同：

| 类型 | 目录 | 更新方式 | 说明 |
|---|---|---|---|
| **规划设计类** | `01_当前指导/` | **覆盖式更新** | 顶层规划、系统定义、资产矩阵、模型影响清单、审计收口分解、接口规范、参数分层规则。每次执行阶段性任务后，对涉及的规划设计文件做覆盖式更新，以最新版本为准。 |
| **实施记录类** | `02_实施记录/` | **增量式更新** | 结构恢复记录、参数敏感性记录、控制策略比较记录。**每次执行阶段性任务后，对涉及的实施记录文件做增量式更新，保留历史执行痕迹。** 阶段性任务 = 每次 git 提交或逻辑上封闭的连续实施线。 |

### 实施记录强制触发

以下任一条件满足时，必须追加当前分卷实施记录：

1. **阶段完成**：Phase X（X=A/B/C/D/...）完成并 git 提交时
2. **S 阶段完成**：S0-S6 任一阶段收敛并 git 提交时
3. **阻塞性问题解决**：模型结构性修复、DAE IC Failure 根因修复、重大阻塞点突破
4. **新模型能力交付**：新控制模式、新电气边界、新初态策略首次可用

**实施记录不得在运行前预写假设数值**——验证结果必须从实际 CSV/workspace/logsout 回填。记录的"完成"以产物存在且验证通过为准，不以模型结构建成为准。

### 实施记录内容要求

每条实施记录至少包含：
- 前置决策引用（指向 `01_当前指导/` 中的对应规划文件）
- 实际完成的工作项（含文件路径、函数名、关键参数）
- 验证证据（数值结果、通过/未通过判据）
- 阻塞点与根因（如有）
- 经验教训（如有）
- 完成状态与未决项

## 子目录规则

| 子目录 | 状态 | 规则 |
|---|---|---|
| `01_当前分卷/` | 当前增量记录 | 只允许追加当前连续实施线；不能把未验证计划写成结果 |
| `02_已封闭/` | 历史实施记录 | 只读追溯，不再追加，也不作为当前平台状态 |

当前规划、模型裁决和验证门槛统一回到 `../01_当前指导/`。旧阶段记录中的"当前规划真源"表述若与新裁决不一致，以当前指导文件为准。
