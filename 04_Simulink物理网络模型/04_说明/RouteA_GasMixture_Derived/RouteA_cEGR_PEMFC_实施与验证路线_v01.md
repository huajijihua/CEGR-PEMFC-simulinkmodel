# RouteA cEGR-PEMFC 实施与验证路线 v01

状态：当前工程化建模准备阶段的执行门禁。
原则：先规格化和匹配，再改模型；保持单模型、单参数源、单全工况入口。

## 1. 实施顺序

### Phase 0：资产与规范治理

- 建立当前模型、参数脚本、运行入口、说明文件和历史证据的角色清单。
- 当前规格文件是后续工作的真源；阶段 A6-A10 文件只用于追溯。
- 审核并压缩 Codex 项目记忆，保留稳定边界，删除旧路线、一次性结果和不再适用的硬约束。

### Phase 1：系统匹配计算

以低/名义/高负载为共同基准，完成以下闭合：

- 电流/功率到氢耗、氧耗、水生成和热负荷；
- 新鲜空气、cEGR、压缩机入口总流、实际入堆氧计量比和阴极压力；
- 供氢压力、回流、排氮和分离接口能力；
- 冷却液流量、允许温差、散热器能力和热平衡。

输出是参数匹配和能力边界，不是产品标定结论。

### Phase 2：接口与控制契约

- 统一空气控制 profile，明确 `target_mdot`、`target_oer` 和直接命令的研究角色。
- 规定 cEGR 变体、目标比值、阀执行器、背压、加湿、冷却和阳极控制的输入/输出语义、单位和饱和边界。
- 处理模型工作区变量、模型内常量和 runner 临时覆盖之间的偏差。

### Phase 3：按优先级升级 BOP

1. 供氧能力与压缩机/中冷/加湿/cEGR 的物理匹配；
2. 供氢压力、循环能力、排氮和水分离；
3. 热管理的泵、散热器、节温和必要时 PTC；
4. 产品级电气接口，仅在研究问题需要时引入。

每次仅升级一个定义明确、具备验证证据的模块；其余模块保留已标注的接口模型。

### Phase 4：配置、标定与验证

台架、车载和产品对象通过 profile 或 `external_case` 派生，不复制主模型。参数辨识必须区分训练与独立验证工况，并保留数据来源、单位、范围、误差和失败案例。

## 2. 验证门

| 门 | 最小证据 |
|---|---|
| 结构门 | 变体路径、关键物理连接、参数引用和子系统接口读回正确 |
| 设备匹配门 | 每个关键 BOP 都有参数来源、能力范围和相对电堆需求的闭合计算 |
| 控制门 | 无 cEGR、0.10、0.30 cEGR 以及低/中/高负载完成；实际 `lambda_ca_in`、压力、RH、温度和执行器约束通过 |
| 数值门 | 冷/热起动、负载阶跃和初始状态扰动不产生未解释的初始化或零交叉失败 |
| 产品门 | 外部数据不污染 `platform_default`；拟合与验证工况分离，结论强度与证据一致 |

## 3. 文件维护规则

1. 一个模型/参数/控制改动必须在同一 Git 提交中更新当前规格或验证记录。
2. 不复制当前数值到多个说明文件；参数脚本、runner 输出和当前规格分别负责数值、结果和语义。
3. 阶段脚本、旧方案和旧说明进入 `99_历史归档` 后不作为默认入口，不参与后续设计决策，除非专题追溯明确引用。
4. `slprj/`、`.slxc` 和活跃运行缓存默认保留且不纳入 Git；不以清缓存作为审计、提交或建模前置动作。
