# RouteA cEGR-PEMFC 实施与验证路线 v01

状态：Phase 1-3 的工作树盘点、规格草案和资产归档已完成；受控 Codex 记忆维护请求已提交；Phase 4 等待与用户共同完成顶层建模规划对齐。
原则：本路线的 Phase 1-4 不修改 `.slx`、不调整 `platform_default`、不新增物理部件或控制律。它们的目的，是把当前 Route A 从“可运行的官方派生模型”明确为“面向工程化系统模型的受控起点”；Phase 4 的产物是与用户共同确认的后续建模顶层规划，不自动触发任何 Simulink 改动。

已完成的 `run_routeA_phase1_matching_audit.m`、九工况结果和参数/接口账本属于既有基线证据，不是本路线的 Phase 编号。它们可用于现状判断，但不得替代后续设备参数、部件能力或独立验证证据。

## 1. 实施顺序

### Phase 1：当前事实、资产与项目记忆清理

目标是先回答“当前究竟有哪些可用资产、哪些只是历史证据、哪些规则会污染主线”。本阶段只读盘点和分类，不改模型。

- 对模型、参数脚本、runner、当前说明、材料池、官方示例、外部案例和 `99_历史归档` 建立角色清单，分类为：当前真源、当前验证证据、材料参考、外部案例或历史归档。
- 逐份检查旧说明的适用版本、参数来源和结论强度；同类内容只保留一个当前入口，其余标记为归档候选，不再默认参与后续决策。
- 审核 Codex 项目记忆与工作流限制，分为保留、更新、删除三类。只保留稳定的模型边界、参数隔离、工具会话和产物纪律；删除已废弃路线、一次性仿真数值、过期文件路径、已否定的硬步骤和会把旧 10 kW/公司资料带回默认链的内容。
- 保持 `platform_default` 与 `external_case` 的隔离；历史外部案例、旧资料和旧标定只能作为显式外部案例或参考证据。

通过门：形成经读回核对的资产/说明/记忆分类表，明确唯一当前模型、参数源、研究入口、材料池入口和归档入口；不存在未标注却仍被视为当前真源的旧文件或记忆规则。

### Phase 2：工程化系统模型定义草案与对齐准备

目标是共同确定未来模型要服务的工程问题、边界和保真度，而不是提前补齐所有设备。成果写回现有工程化规格，不新增平行 Markdown。

- 固定“通用燃料电池系统集成设计与参数匹配”为总目标；当前以官方案例约 50 kW 数据作为最初参考尺度、参数锚点和验证载体，而不是把 50 kW 固定为最终应用规模。保留官方 Gas Mixture PEMFC 派生骨架和单模型/单参数源/单全工况入口原则。
- 定义工程化系统的四个域：供氧与 cEGR、供氢与阳极水管理、热管理、电气接口。明确每个域的目标设备、物理机理、必要测量、控制角色和本阶段不建模内容。
- 固定建模来源与表达范围：官方燃料电池系统案例、官方 FuelCell/Simscape 网络和模块级复用优先；官方资产未覆盖的内容才进入文献或明确物理化学方程路线。模型保持复杂的零维集总参数系统级定位：零维只表示不求解空间场分布，不表示模型简单。电堆、多域物理网络、BOP、控制器和参数匹配通过守恒/本构方程、常微分/代数关系、必要的微分代数求解、物理端口和变量传递耦合；不在 Route A 内承担几何结构或偏微分方程场建模。
- 明确研究场景不是系统能力边界：系统应允许独立调节进气量、温度、湿度、压力、回流比、恒电流/恒电压以及稳态/瞬态边界；实际研究只选代表性工况，不穷举全部参数组合。
- 固定代表性场景：无/低/中 cEGR 下的低/中/高负载稳态，以及一次无 cEGR-开 cEGR-无 cEGR 的切换瞬态。切换瞬态在编译有 cEGR 拓扑下通过目标回流比 `0 -> representative -> 0` 实现，禁止运行中切换 `routeA_cegr_enabled` 变体。
- 明确当前模型是系统级物理网络和方案筛选平台，不是机械总成或认证模型。
- 冻结 `u/w/y/z`、单位、时序、初始状态、`platform_default` 与 `external_case` 边界，以及“控制命令不等于物理能力证明”的验收原则。
- 对每个目标部件明确预期保真度、参数来源等级、可验证证据和升级触发条件；没有官方复用依据、文献依据或明确方程的设备责任保留为 L2 待证接口，不得用未经验证的 MATLAB Function 经验公式提前补齐。

通过门：形成一份工程化系统定义草案和待对齐清单，包括四域架构、设备清单、研究问题、保真度边界、参数来源层级、控制/观测接口和验收用途。草案可进入资产整理，但不得据此进入具体 BOP 改模或参数拟合。

### Phase 3：工程资产全面梳理、归档与当前真源收口

目标是在 Phase 1 分类和 Phase 2 定义草案的基础上，对现有工作资产做减法，形成清晰、可追溯且不相互矛盾的当前工作树。本阶段仍不改 `.slx`。

- 合并可合并的说明、脚本说明和审计入口；当前规范只保留模型规格、实施路线、材料池/候选比较、项目 `AGENTS.md` 和必要 runner。历史阶段文件、双模型比较、废弃方案和重复说明进入现有 `99_历史归档`，并保留简短索引。
- 对模型、参数源、全工况 runner、审计 runner、官方示例、材料池、外部案例和历史证据建立可追溯关系；不复制主模型，不把材料参考或外部案例伪装成当前默认资产。
- 按 Phase 1 的结论更新或删除 Codex 过期项目记忆，避免旧路线、旧探针和一次性结论继续约束新任务；只保留已验证的长期边界与必要入口。
- 建立一次 Git 可追溯基线；不提交 `slprj/`、`.slxc`、base workspace 结果或运行缓存，也不以清缓存作为前置动作。

通过门：当前工作树、说明真源、历史归档和 Codex 长期记忆彼此一致；后续顶层规划所需的模型、证据、材料和待确认问题都有唯一入口。未通过该门，不依据分散旧文件制定建模路线。

### Phase 4：后续建模顶层规划设计与共同对齐

目标是以已整理的资产和工程化定义草案为输入，与用户共同决定“未来具体建什么、为何建、先建什么、保持什么不变、如何验证”。这是防止后续 Simulink 建模偏离研究目标的最终对齐步骤，不是启动改模的授权。

- 按五项工程化准则审视当前 Route A：官方案例派生与物理网络真实性；参考尺度电堆与 BOP 参数闭合；控制逻辑与代表性研究场景支持能力；子系统布局、变量耦合和可维护性；参数化、拟合和验证的复用边界。
- 将建模来源作为结构性审查门：每个设备模块必须能够追溯到官方案例/官方模块复用，或追溯到文献和明确物理化学方程；仅由 MATLAB Function 经验公式构成的等效设备模块不得进入当前主模型。
- 将现有能力、L2 待证能力和阻断性缺口分别列出，并逐项标明“已验证事实、基于证据推断、待确认假设”。已有九工况和参数审计只能作为证据输入，不可扩大为设备能力或系统应用结论。
- 设计未来模型的顶层演进方式：四域子系统的目标边界和复用关系，单模型/单参数源/单入口如何维持，边界参数和设备参数如何配置，何时需要参数拟合或局部高保真校核。
- 共同确定后续专项的优先级和边界。每个候选专项必须说明目标部件、允许/禁止改动、所需数据、参数来源、接口影响、最小验证、退出条件和与其他子系统的隔离方式。
- 将尚需用户决策的内容显式保留，例如设备保真度、边界参数范围、可获得的部件数据、参数拟合目标和验收强度；不由 agent 擅自假定。

当前规划建议按以下顺序推进：供氧与 cEGR 参数匹配及接口闭合；热管理参数匹配与热控制闭合；供氢与阳极水管理参数匹配；电气接口与辅电边界。该顺序只表示证据和耦合关系上的优先级，不代表自动修改模型。

#### 首个专项工作包：供氧与 cEGR 参数匹配及接口闭合

- **目标**：闭合电堆与供氧/cEGR 域的流量、组分、压力、湿度、回流和控制接口，形成模块来源、参数能力和验证缺口的单一证据链。
- **对象**：官方气体混合电堆网络、空气源与压缩机流量源/地图接口、中冷、阴极加湿、cEGR 阀/回流管、排气/背压、水分离、入口混合、相关传感器及空气/cEGR 控制链。
- **来源门**：优先官方案例与官方 Simscape/Simulink 模块级复用；官方未覆盖部分才采用文献或明确物理化学方程。没有上述依据的内容保留为 L2 或 `deferred`，不得用经验性 MATLAB Function 等效设备。
- **允许内容**：只读结构与参数读回、参数注册和单位核查、反应/空气/cEGR 能力账本、接口契约整理、现有代表性矩阵证据整理和数据缺口定义。
- **禁止内容**：改 `.slx`、改 `platform_default`、改控制律或 runner、增加设备等效模块、引入空间场模型，以及把 OER/回流命令当作压缩机、阀、加湿器或分离器能力证明。
- **最小验证**：来源和参数状态齐全；质量/组分/压力/RH/热量计算有限且量纲正确；无 cEGR 回流为零；低/中 cEGR 跟踪、压差方向和阀面积边界正确；`lambda_ca_in` 满足门槛；请求流量与压缩机地图有效范围一致；无数据能力项明确标为待证。
- **隔离与退出**：冻结电堆、供氢、热管理和电气接口，只读取其边界需求。完成后输出专项缺口和最小变更建议，是否进入 Simulink 修改必须另行授权。

通过门：用户与 agent 共同确认一份后续建模顶层规划，包含研究目标、系统边界、子系统演进顺序、参数与验证路线、明确不变项、待确认项和每个专项的验收门。此门通过后，是否启动第一个 Simulink 专项仍由用户单独授权。

## 2. 规划阶段门禁

| 门 | 本轮必须回答的问题 | 禁止越界 |
|---|---|---|
| 事实门 | 当前模型、参数、脚本、说明、材料、记忆各自是否有唯一角色？ | 不依据旧文件或记忆直接改模型 |
| 定义门 | 通用系统集成设计研究什么、不研究什么、以何证据验证？ | 不把系统级平台表述为完整机械或电气系统，不把经验公式等效模块当作物理设备 |
| 归档门 | 当前工作树、说明、材料和记忆是否已收口为可追溯的唯一入口？ | 不依据分散旧文件或旧记忆制定建模路线 |
| 对齐门 | 后续顶层规划是否经共同确认，并保留所有未决选择？ | 不自动批准模型改动、不复制主模型、不污染 `platform_default` |

## 3. 进入 Simulink 后的持续验收门

| 门 | 最小证据 |
|---|---|
| 结构门 | 变体路径、关键物理连接、参数引用和子系统接口读回正确 |
| 设备匹配门 | 每个关键 BOP 都有参数来源、能力范围和相对电堆需求的闭合计算 |
| 控制门 | 无/低/中 cEGR 的低/中/高负载代表性稳态，以及一次目标回流比 `0 -> representative -> 0` 切换瞬态完成；实际 `lambda_ca_in`、压力、RH、温度和执行器约束通过 |
| 数值门 | 冷/热起动、负载阶跃和初始状态扰动不产生未解释的初始化或零交叉失败 |
| 应用边界门 | 外部数据不污染 `platform_default`；拟合与验证工况分离，结论强度与证据一致 |

## 4. 文件维护规则

1. 本路线、工程化规格和材料池分别负责阶段门禁、模型目标边界和材料/候选依据；不新增同职责说明文件。
2. 一个模型、参数或控制改动必须在同一 Git 提交中更新当前规格或验证记录；规划阶段的文档/归档变更不得伪装成模型验证。
3. 阶段脚本、旧方案和旧说明进入 `99_历史归档` 后不作为默认入口，不参与后续设计决策，除非专题追溯明确引用。
4. `slprj/`、`.slxc` 和活跃运行缓存默认保留且不纳入 Git；不以清缓存作为审计、提交或建模前置动作。
