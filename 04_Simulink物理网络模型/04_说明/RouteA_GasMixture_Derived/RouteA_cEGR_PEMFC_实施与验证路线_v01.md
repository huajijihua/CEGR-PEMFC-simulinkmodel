## 0. 顶层规划总览

### 0.1 最终建模目标

Route A 的长期目标不是完成一次工况计算，而是形成一套以 Simulink/Simscape 为核心的、可复用的工程化燃料电池系统集成设计与参数匹配平台。平台应以电堆为核心，组织供氧与 cEGR、供氢与阳极水管理、热管理、电气接口以及控制/观测架构，在系统级完成物质、能量、压力、湿度、温度、电气和控制耦合的计算。

模型的最终价值体现在四个方面：

1. 能根据电堆需求和边界条件完成 BOP 能力匹配，而不是孤立调节模块参数。
2. 能用同一个模型和参数体系研究无/低/中 cEGR、低/中/高负载稳态以及代表性切换瞬态。
3. 能通过模块化边界、统一接口和参数注册表持续替换或升级设备模型，而不破坏其他子系统。
4. 能形成可追溯的参数来源、能力范围、验证证据和后续标定路径，为进一步研究提供稳定系统级基础。

### 0.2 最终模型形态

最终模型是复杂的零维集总参数系统级物理网络，不追求在 Simulink 内求解几何空间场分布。它由以下层次组成：

- **核心设备层**：电堆 MEA、气道、反应、电压、热和电气端口。
- **辅助系统层**：供氧/cEGR、供氢/阳极水管理、热管理和电气接口四域。
- **控制与观测层**：负载、空气、cEGR、压力、湿度、温度、热管理和诊断控制。
- **参数与研究层**：`platform_default`、显式研究场景、派生量、`external_case`、参数优先级和验证矩阵。

各层通过官方物理网络、守恒/本构方程、物理端口、信号接口和参数契约耦合。MATLAB MCP/Simulink 工具用于模型读回、参数核查、结构检查和仿真验证；它是实施和验证手段，不替代顶层模型定义。

### 0.3 长期实施路径与预期成果

Stage 0 已由 Phase 1-4 完成；以下 Stage 1-5 是后续系统模型演进的长期工作包。每个阶段都必须同时回答“研究什么、改什么、依据什么、如何验证、产出什么”。

#### Stage 1：电堆核心与供氧/cEGR 联合匹配

- **目标**：以电堆反应、功率、电压和热需求为锚点，闭合空气供给、氧计量、cEGR 回流、阴极压力/RH 和相关控制边界。
- **系统对象**：电堆 MEA/气道/热电端口、空气源与压缩机接口、中冷/加湿接口、cEGR 阀与管路、排气/背压、水分离、入口混合、测量和空气/cEGR 控制链。
- **核心问题**：电堆需求是否能推导出有限且量纲正确的空气和回流需求；实际 `lambda_ca_in` 是否满足门槛；回流目标是否由正确压差和阀工作区间实现；压缩机请求是否在地图有效范围内。
- **重点参数**：电池数量、活性面积、负载/电流关系、反应与热电需求、空气质量流量和组分、压力/RH/温度边界、cEGR 比值、阀面积/压差、背压和加湿控制。只将影响闭合或验收的 `P0/P1` 参数纳入主动研究。
- **接口与场景**：保持 `u/w/y/z` 契约；先做端口级读回和中负载 `noCEGR/0`、`withCEGR/0.10`、`withCEGR/0.30`，再扩展低/高负载稳态，最后做 `0 -> 0.10 -> 0` 瞬态。
- **实施路径**：来源核查和参数账本 → MATLAB MCP 只读模型/端口/参数读回 → 识别真实缺口 → 必要时只对一个物理边界做小步封装、修复或增强 → `model_check`、端口读回和最小回归。
- **阶段产出**：电堆-BOP 联合能力账本、端口级接口表、模块来源/缺口表、代表性工况回归证据和下一阶段热管理输入。
- **退出条件**：电堆和供氧/cEGR 的质量、组分、压力、湿度、热量和控制关系闭合；无 cEGR/有 cEGR/切换场景满足现行门槛；未具备设备数据的能力明确标为 L2 或 `deferred`。

#### Stage 2：热管理参数匹配与热控制闭合

- **目标**：把电堆反应热、冷却回路、堆温目标、环境换热和热控制纳入与气体系统一致的能力匹配。
- **系统对象**：电堆热端口和冷却通道、冷却泵、冷却液边界、散热器/环境换热、节温或旁通控制、必要时 PTC 和温度测量。
- **核心问题**：电堆热负荷能否由冷却流量和温差带走；泵和回路压降是否匹配；散热能力是否有 UA/风量或等价证据；堆温在低/中/高负载和 cEGR 变化下是否稳定。
- **重点参数**：反应热、冷却液物性、流量、`DeltaT`、泵特性、回路压降、散热器 UA/风量、环境边界、堆温目标和热控制参数。缺少泵/换热数据时只保留工程量级和 L2 状态。
- **接口与场景**：输入承接 Stage 1 的电堆热负荷和负载轨迹；输出堆温、冷却流量、进出口温度、热量和执行器饱和；优先验证低/中/高负载稳态，再验证负载阶跃或 cEGR 切换引起的热响应。
- **实施路径**：热量账本 → 热液网络和参数来源读回 → 冷却能力/温差/环境换热闭合 → 只在证据支持时升级泵、换热或控制模块 → 热平衡和动态回归。
- **阶段产出**：冷却能力边界、堆温控制参数、热量平衡证据、散热能力缺口和与供氧/cEGR 的热耦合接口。
- **退出条件**：目标工况下热量守恒有限，冷却需求与设备能力范围一致，堆温和执行器约束通过；无 UA、风量或泵数据的结论保持为待证，不宣称真实散热能力。

#### Stage 3：供氢与阳极水管理参数匹配

- **目标**：形成氢源、减压/喷射、阳极回流、排氮、液水分离和 purge 控制的系统级闭合，并与电堆氢耗和压力需求匹配。
- **系统对象**：氢源和减压接口、比例阀/喷射器、循环泵或引射器、阳极气道和容腔、分离器、purge 阀、压力/流量/组分/液水测量及相关控制。
- **核心问题**：氢耗、供氢压力和回流能力是否满足电堆需求；阳极 lambda、惰性气体积累、purge 和液水管理哪些可观测、哪些仍待证；循环器/引射器能力是否有真实来源。
- **重点参数**：氢源压力/温度/组分、氢耗、供氢流量、阀压降/流通特性、循环器能力、分离效率、purge 逻辑和阳极压力边界。没有数据的循环/分离能力不得用经验公式补齐。
- **接口与场景**：承接电堆电流、温度和热管理边界；通过 `w` 接入氢源，通过 `u` 表达供氢/回流/purge 控制，通过 `y/z` 区分测量和审计真值；验证低/中/高负载下的供氢和水管理边界。
- **实施路径**：氢耗和压力需求账本 → 官方结构/方程来源核查 → 回流、排氮和液水观测能力判断 → 有数据时进行局部模块升级 → 与电堆负载和热状态联合回归。
- **阶段产出**：氢侧能力账本、阳极接口契约、回流/分离/purge 证据等级、可观测性缺口和适用工况边界。
- **退出条件**：氢耗和供氢压力需求闭合，已具备的回流/水管理能力通过最小验证，未具备阳极 lambda 或循环器数据的部分明确限制结论强度。

#### Stage 4：电气接口与辅电边界

- **目标**：在研究问题确实需要时，把电堆电气输出、受控负载、DCDC、母线和辅电消耗纳入系统级功率匹配。
- **系统对象**：电堆电压/电流/功率端口、受控负载、DCDC 边界、母线/辅电负载和电气测量；不默认扩展为完整电气系统。
- **核心问题**：堆端功率与负载请求如何匹配；辅件功耗是否影响净功率；DCDC 的效率、限值和动态是否有来源；电气边界是否会反过来改变空气、热管理和控制需求。
- **重点参数**：电堆 I-V-P 关系、负载轨迹、DCDC 功率/效率/限值、辅电负荷和电气控制约束。只有研究问题触发时才将 DCDC/辅电参数纳入 `P0/P1`。
- **接口与场景**：冻结现有电堆电气输出和受控负载契约；按需增加净功率、辅电和母线测量；验证负载变化、稳态功率平衡和必要的瞬态电气响应。
- **实施路径**：明确研究触发条件 → 电气端口和功率账本读回 → 来源和接口设计 → 只对有数据支撑的边界进行小步扩展 → 与气体/热管理回归。
- **阶段产出**：电气边界定义、堆端/净端功率账本、辅电影响、DCDC 纳入条件和最小验证方案。
- **退出条件**：电气设备责任和接口不再含糊，功率平衡和限制条件可验证；若研究问题不需要，则保持受控负载边界，不为完整性而扩展模型。

#### Stage 5：参数化、标定与验证闭环

- **目标**：把已闭合的系统模型转化为可复用的参数 profile，并通过数据和独立验证提高预测可信度。
- **系统对象**：`platform_default`、显式 `external_case`/profile、`P0/P1` 参数集、派生关系、观测 KPI、标定数据和验证数据；不是新的物理子系统。
- **核心问题**：哪些参数可由现有数据辨识；哪些参数高度相关或不可观测；训练/验证如何分离；误差、物理门槛和适用范围如何同时满足；何时需要局部高保真工具校核。
- **重点参数**：先从影响系统闭合和研究结论的 `P0/P1` 开始，按敏感性筛选 `P2`；`deferred` 参数只保留数据需求，不进入全量扫掠。
- **接口与场景**：保持同一模型和参数契约，外部 profile 只能显式接入；验证至少覆盖代表性稳态、切换瞬态和独立边界，记录误差、失效工况和不确定性。
- **实施路径**：数据审查 → 参数可辨识性/敏感性分析 → 训练/验证划分 → 受控拟合或方程参数化 → 系统级复验 → 必要时将局部空间机理结果以适用范围明确的参数/代理/ROM 回灌。
- **阶段产出**：可复用参数 profile、标定记录、验证报告、误差和不确定性边界、失效工况清单及高保真协同触发条件。
- **退出条件**：参数来源、拟合边界、验证边界和结论强度一致；模型不会因为低误差拟合而失去物理意义；可明确说明哪些能力已经验证、哪些仍待证。

控制与数值健壮性是贯穿各阶段的横向工作线，不单独等待所有 BOP 完成。每个阶段都采用“来源确认 → 参数/接口闭合 → 最小模型动作 → 结构读回 → 最小回归 → 决定是否扩展”的闭环。

### 0.4 顶层规划完成标准

本轮顶层规划的完成，不以已经修改 `.slx` 为标准，而以 Stage 1-5 均已明确目标、对象、核心问题、重点参数、接口/场景、实施路径、阶段产出和退出条件，并且这些阶段之间的依赖关系、横向控制/数值工作线和长期验证路线已经明确为标准。满足后，后续 Simulink 工作只需按当前路线进入相应专项，不再重新讨论项目总方向。

## 1. 实施顺序

### Phase 1：当前事实、资产与项目记忆清理

目标是先回答“当前究竟有哪些可用资产、哪些只是历史证据、哪些规则会污染主线”。本阶段只读盘点和分类，不改模型。

- 对模型、参数脚本、runner、当前说明、材料池、官方示例、外部案例和 `99_历史归档` 建立角色清单，分类为：当前真源、当前验证证据、材料参考、外部案例或历史归档。
- 逐份检查旧说明的适用版本、参数来源和结论强度；同类内容只保留一个当前入口，其余标记为归档候选，不再默认参与后续决策。
- 审核 Codex 项目记忆与工作流限制，分为保留、更新、删除三类。只保留稳定的模型边界、参数隔离、工具会话和产物纪律；删除已废弃路线、一次性仿真数值、过期文件路径、已否定的硬步骤和会把旧 10 kW/公司资料带回默认链的内容。
- 保持 `platform_default` 与 `external_case` 的隔离；历史外部案例、旧资料和旧标定只能作为显式外部案例或参考证据。

通过门：形成经读回核对的资产/说明/记忆分类表，明确唯一当前模型、参数源、研究入口、材料池入口和归档入口；不存在未标注却仍被视为当前真源的旧文件或记忆规则。

### Phase 2：工程化系统模型定义草案与对齐准备

目标是共同确定未来模型要服务的工程问题、边界和保真度，而不是提前补齐所有设备。成果写回现有工程化规格，不新增平行 Markdown。

#### 恒功率边界与 pre/mid/post 解读

以下内容只解释旧 120 s 暖机 smoke 的方向反转，不作为当前 Stage 1 的性能验收；稳态锚定结果见后文。

当前 `Electrical Load` 的活动输入模式是 `Drive cycle`。`Drive Cycle Power Demand` 从 `[drive_cycle_time, drive_cycle_power]` 读入功率需求，经 `PS Divide` 按 `i=P/v` 生成受控电流源命令；因此 `drive_cycle_power=[0,50.96,50.96]` 是外部负载功率请求，不是电堆内部独立的电压或电流控制器。

- pre 到 mid 中，O2 质量分数由 `0.220141` 降至 `0.206259`，cEGR 增加，但堆温也由 `36.86` 升至 `71.41 °C`，且恒功率边界下电流由 `127.490` 降至 `125.385 A`。降低电流会降低极化损失，升温会改善当前堆模型中的反应/欧姆项；这两个作用在本次运行中超过了 O2 降低的负作用，所以电压由 `399.722` 升至 `406.430 V`。由 `P=VI`，电压升高必然伴随电流降低；不能把该结果解释为 cEGR 单独提高了电压。
- 当前模型已有 `Ramp Current Demand` 和 `Step Current Demand` 两个电流需求变体，可以开展给定电流轨迹下的试验；但 Stage 1 尚未建立与 cEGR 事件联动的恒流审计入口。恒流下应直接读回 `P=VI`，若同热状态下 cEGR 使电压降低，功率将随之降低。
- 当前模型没有恒压闭环。`Voltage Sensor` 的读数用于功率需求的 `P/v` 换算和观测，没有电压误差控制器；恒压研究需要单独授权增加电压控制接口。若同热状态下保持电压而 cEGR 使可维持电流降低，功率才会相应降低，方向不能由本次恒功率结果直接代替。
- 此处记录的是重构前打开态目标回零的残余流量，不再作为严格 no-cEGR 结论。当前严格 no-cEGR 通过 `routeA_cegr_valve_mode_id=0` 选择 `Infinite Flow Resistance (FC)`，要求主 cEGR 流严格为零；打开态目标回零仍可能保留管路/控制器状态记忆，但可作为 `mode=1` 零目标近似参考，不属于关闭态验收。
- post 继续出现电压升高、电流降低，主要是堆从初始冷态继续升温和状态演化，而不是“无 cEGR 后没有回到 pre”。transition post 的堆温为 `80.135 °C`、电压 `408.172 V`；独立 noCEGR baseline 的 post 为 `80.136 °C`、`408.202 V`，两者已接近。真正的 noCEGR 因果对照应在相同热/压力/湿度/控制器状态下进行，不能拿早期冷态 pre 窗口作为回归目标。

本阶段不以冷启动作为性能研究起点。唯一的 `platform_default` 初值保存在 `01_模型/RouteA_GasMixture_Derived/RouteA_platform_default_initial_state.mat`：它是完整的 `Simulink.op.ModelOperatingPoint`，而非只写入几个温度或压力标量；因此同时携带堆温、气体库存、湿度、压力、流量、组分和控制器内部状态。当前正式文件的 metadata 为 `RouteA_platform_default_initial_state_v03_mode1`、`cegrValveModeId=1`、`egrReferenceKind=mode1_zero_target_near_zero`、`cegrValveMaxArea_m2=1.96349540849e-4`；它由零目标预热候选在周期相位门通过后原子提升。生成工况为 `j=0.1 A/cm^2`、`A=280 cm^2`、恒 `I=28 A`、`routeA_cegr_enabled=true`、`mode=1` 且目标回流为零，实际回流为近似零。状态快照模型时间为 `4823.613210161 s`，取阳极最近一次吹扫后 `100 s` 的相位；该运行点的阳极吹扫周期约 `789.731 s`。后续每个正常性能研究都从这同一状态重新起算，不以某一试验的结束状态作为下一试验初值。

#### 本轮方法论总结：周期运行性能与运行态初值

本轮的首要结论不是“系统没有稳态”，而是该系统在存在阳极氮气累积和吹扫控制时，不能用所有变量严格恒定的静态点定义正常工作性能。电压随时间的周期性变化与阳极库存/吹扫事件相符；只要研究边界、初始相位、研究时长和统计窗口保持一致，它就是可解释、可对照的系统运行行为。

因此，Stage 1 后续稳态性能研究采用固定时长的末段统计而不是单个末值：对当前 `j=0.1 A/cm^2` 首轮矩阵，所有案例从同一个保存运行态初值独立启动，运行逻辑 `600 s`，以末段 `[540,600) s` 的均值作为边界条件下的性能代表值，并同步记录该窗口的 span/标准差。cEGR、气、热、湿、压等任一边界的作用，均以同一逻辑时间窗口、同一初值、零实际回流参考的均值相减获得；运行内 pre-to-post 差只保留为库存/周期演化诊断。

本轮的第二个结论是，初始值必须服务于研究问题。对于暂不研究冷启动的正常性能矩阵，冷态环境初值会把升温、加湿、气体库存建立等长暂态混入计算，既降低计算效率，也破坏控制变量法。保存的完整 operating point 使温度、湿度、压力、流量、组分和控制器状态从正常运行相位开始；冷启动只在未来作为独立专题启用。`0 -> 0.10 -> 0` 试验的作用是证明模型和接口具备瞬态研究能力，不能替代上述稳态性能统计。
