## 1. 定义

Route A 是一个面向通用燃料电池系统集成设计与参数匹配的模块化平台。当前以官方 Gas Mixture PEMFC 案例提供的约 50 kW 数据作为参考尺度和验证载体，因为该案例参数相对完整且来源明确；50 kW 不是平台的最终规模限制。平台以单一 Simulink/Simscape 物理网络为核心，通过参数层和编译期 cEGR 变体覆盖无 cEGR 与有 cEGR 工况，并保留按边界参数和设备参数重新配置的能力。

本模型用于研究电堆与供氧、供氢、热管理、受控负载接口之间的物理耦合、参数匹配和控制约束。它当前是系统级物理网络和集成设计平台，不承担三维机械装配或完整高压电气系统的建模责任。

### 1.1 建模保真度与系统级边界

Route A 的设备模块保真度按以下来源优先级确定：

1. 优先复用官方燃料电池系统案例、官方 FuelCell/Simscape 物理网络和可复用的 Simulink/Simscape 模块；模块级复用必须保持原有物理端口、守恒关系和参数语义。
2. 官方资产未覆盖的设备责任，必须以可追溯文献或明确的物理化学原理方程为基础，包括质量、动量、能量、组分、相平衡和电化学关系等。
3. 只有工程量级假设或缺少来源的数据，保留为参数占位、边界条件或 L2 待证接口；不得据此宣称设备机理、效率或能力已经建立。
4. MATLAB Function 可用于控制逻辑、状态机、代数换算、参数装配和 KPI 计算，但不得以未经验证的经验公式作为设备物理模块的唯一基础。

Route A 是复杂的零维集总参数系统级模型。“零维”只限定空间分布建模边界，不代表模型简单，也不降低对物理机理和系统耦合的要求。模型由电堆机理、气体/水/热/电多域网络、BOP 设备、控制器、守恒与本构关系、动态状态以及参数匹配关系共同组成，并通过常微分/代数关系、必要的微分代数求解、Simscape 物理端口和信号变量传递实现耦合。模型以第一性原理、守恒定律和可追溯机理方程为主要依据，不在 Route A 内求解几何结构、空间分布或偏微分方程场；需要空间场分布时，再由独立高保真工具承担局部校核，不改变 Route A 的系统级定位。

## 2. 工程化目标

1. 建立可复用的燃料电池系统集成设计方法：以电堆为核心，完成供氧、供氢、热管理和电气接口之间的设备选型、连接关系、能力匹配和控制边界设计。
2. 基于可追溯的物理网络和参数来源，计算功率、物质、压力、温度、湿度与热负荷的系统级响应；当前用官方约 50 kW 案例作为基准工况和量级锚点。
3. 由电堆功率和反应需求推导 BOP 的流量、压力、热管理和控制能力要求，而不是孤立调整模块参数。
4. 维持一套模型、一个 `platform_default` 参数源和一个全工况研究入口；外部设备或边界数据只能经显式 profile 或 `external_case` 接入。
5. 允许以不破坏系统接口的方式，将 L2 设备接口逐步替换为经过参数匹配或标定的部件模型，并支持未来更换电堆规模或设备配置。

## 3. 系统边界与架构

| 工程域 | 当前模型责任边界 | 当前保真度定位 |
|---|---|---|
| 电堆核心 | MEA、阴阳极气道、出口容腔、堆热和电气端口 | 官方物理网络内核 |
| 供氧与 cEGR | 空气源、压缩机/地图、入口混合、中冷接口、阴极加湿、回流阀/管、排气、背压和阴极水管理接口 | 官方物理网络加 L2 设备接口 |
| 供氢 | 储氢、减压、阳极加湿、回流、排氮与阳极水管理接口 | 官方主结构加 L2 回流/分离接口 |
| 热管理 | 冷却通道、泵、散热器、环境换热和控制接口 | 官方热液网络，待做能力匹配与控制闭合 |

| 控制与观测 | 空气、cEGR、背压、湿度、冷却接口以及 KPI | 研究级控制接口；不承担完整系统控制软件 |

cEGR 是供氧/阴极排气水管理域的一条可切换物理支路，不是并行的第五套 BOP。无 cEGR 通过 `cEGR_Mode_Selector` 的官方无限流阻隔离实现；有 cEGR 保留排气、水分离、阀、回流管和入口混合链。

## 4. 接口原则

| 类别 | 当前或后续接口 |
|---|---|
| 控制输入 `u` | 功率请求、空气模式与总压缩机流量/新鲜空气等效 OER 目标、cEGR 模式与目标比值、阴极出口压力目标、加湿器与冷却控制量 |
| 外界输入 `w` | 环境压力/温度/RH、氢源状态和组分、初始状态以及用户定义的边界参数 |
| 控制测量 `y` | 电流、电压、功率、压缩机入口流量、cEGR 流量/比值、阴极出口压力、RH、温度、冷却相关测量 |
| 审计真值 `z` | 实际入堆氧质量流和 `lambda_ca_in`、内部组分、热量、分离水 KPI、执行器饱和与物理节点状态 |

控制命令不能代替物理验收。`routeA_air_control_mode_id=2` 的 legacy 输入 `routeA_target_oer` 按新鲜空气 O2 质量分数 `0.234` 将电流换算为**总压缩机流量**设定；在 cEGR 开启后，它不等于实际入堆 `lambda_ca_in`。因此本规格将其称为“新鲜空气等效 OER”，而将 `lambda_ca_in` 定义为按实际入堆 O2 质量流和电流计算的审计真值。cEGR 评价必须以混合气组分、实际氧计量比和压力链为准。

`routeA_cegr_valve_mode_id` 是正常研究工况唯一的编译期物理开关：`0` 为 `EGRValveRestriction` 的官方无限流阻隔离，`1` 为官方局部限制连通；二者均只在独立仿真前 `update diagram` 生效，禁止在单次连续仿真中切换。正常 runner 固定根部 `routeA_cegr_enabled=true`；根部关闭加内部关闭会使 EGR 管段双重隔离并欠定，因此该根部 Variant 只用于结构回归。`mode=0` 是独立仿真的严格无 cEGR 参考；后续技术研究默认 `mode=1`，通过目标循环比在同一仿真内实现零目标、正循环比和回零。`mode=1` 的零目标只能称为近似零 cEGR 或零目标参考，不能替代 `mode=0` 的严格隔离验收。关闭态的 AR 物理信号由 `PS Terminator` 接收，并由只服务该信号网络的官方 `Solver Configuration` 提供求解配置；该配置不连接 A/B 气体网络。`cegr_valve_open_min_area` 仅约束打开态限制阀，零 cEGR 的严格验收量是零回流和完整排气流，而不是极小面积。连续 Simscape 物理量按 variable-step 处理。

### 4.1 第 3 批已对齐：`u/w/y/z` 接口契约

第 3 批已对齐接口的语义分层：`u` 是控制命令，`w` 是外部边界，`y` 是控制可用测量，`z` 是审计真值。该分层是现有 Simulink/Simscape 物理端口和信号接口的契约分类，不要求新增四个同名根端口，也不允许把控制目标直接当作实际设备能力。

- `u`：功率/电流/电压请求、总压缩机流量或新鲜空气等效 OER 目标、cEGR 目标比、背压目标、加湿和冷却控制量。
- `w`：环境压力/温度/RH、氢源状态、初始状态和用户定义边界参数。
- `y`：电流、电压、功率、流量、实际 cEGR 比、阴极出口压力、RH、温度和冷却相关测量。
- `z`：实际入堆氧流量、`lambda_ca_in`、内部组分、热量、L2 水分离 KPI（非物理排液）、阀面积/压差、执行器饱和和物理节点状态。

进入任何 `.slx` 改动前，必须完成端口级只读读回：确认名称、单位、方向、连续/离散属性、变量所有权和可观测性。读不出的量标记为 `unobservable`，不为补齐契约临时新增物理模块；`platform_default`、`external_case` 和 `routeA_cegr_enabled` 属于参数/配置层，不归入 `u/w/y/z`。

已完成的参数匹配与接口契约审计只在 base workspace 生成 `routeA_phase1_audit`。其包含反应/冷却账本、参数注册表、接口契约、被动 cEGR 诊断和缺口表；不导出 CSV、图片、模型副本或缓存。若当前 base workspace 已有同一模型、同一 9 工况矩阵定义的完整结果，审计入口复用该结果，只补充两条被动 cEGR 诊断。

## 5. 保真度与参数规则

1. 官方 `FuelCell_lib`、官方案例和官方系统级模块直接覆盖的物理内容优先复用，并优先采用模块级复用而不是重新编写等效模块。
2. 官方资产未覆盖的内容，必须以可追溯文献或明确物理化学方程搭建；方程、状态量、边界条件和适用范围必须能够单独审计。
3. 中冷器、水分离器、压缩机机械动态、氢循环装置、加湿器水热传递、节温与 PTC 等未充分实现内容必须标明为 L2 接口、待升级设备或待标定模块，不得用经验性 MATLAB Function 公式补齐并冒充设备机理。
4. MATLAB Function 仅用于控制、逻辑、代数换算、参数装配和诊断计算；若其承担设备物理责任，必须有独立方程和来源证据，不能仅凭脚本无报错或曲线拟合成立。
5. 每项可调参数后续必须归入机理参数、设备能力参数、控制参数或数值参数，并记录单位、来源、适用范围和验证状态。
6. 不以数值收敛替代工程真实性；也不因暂缺设备数据而提前建立无法验证的高保真动态。

### 5.1 证据等级与复用边界

1. “已验证事实”仅限模型读回、官方来源、已完成的当前 runner 验收或独立数据直接支持的结论。
2. “基于证据推断”可用于提出量级、架构或升级优先级，但不得写成部件能力、效率或系统/设备性能。
3. “待确认假设”必须保留为 `deferred`，并在进入任何专项前转化为明确的数据需求或验证任务。
4. 外部配置只能通过 profile 或 `external_case` 接入；参数拟合需单独记录训练/验证边界、适用范围、误差和失效工况。

### 5.2 第 2 批已对齐：模块保真度分类与 MATLAB Function 处置

所有设备和子系统模块在进入后续改模或参数专项前，统一按以下状态登记：

| 状态 | 判定条件 | 结论用途 |
|---|---|---|
| `official_reuse` | 来自官方案例、官方 FuelCell/Simscape 网络或可追溯的官方模块级复用 | 可作为当前物理网络和参数语义依据 |
| `equation_based` | 有可追溯文献和明确的物理化学方程、边界条件及适用范围 | 可作为机理模块候选，需通过最小验证 |
| `l2_interface` | 仅承担系统级边界、能力占位或接口传递，来源/能力尚未闭合 | 可用于系统耦合和工况计算，不宣称设备能力 |
| `deferred` | 来源、方程、参数或验证证据不足 | 不进入当前物理结论，保留为后续数据/专项需求 |

第 2 批已对齐的 MATLAB Function 规则：控制、逻辑、参数装配、代数换算和诊断计算可以保留；仅由经验公式承担设备物理责任的模块不得作为当前设备模型或验证证据。此类模块暂不直接删除，以保持可追溯和可运行性，待有正式来源或方程替代时单独处理。

### 5.3 第 4 批已对齐：参数层级、所有权与重点参数原则

参数治理采用“唯一来源、显式场景、统一派生、外部隔离”的层级：`platform_default` 保存权威独立参数；研究场景只显式传入工况边界和控制目标；由电堆需求或设备关系计算出的量由统一装配/runner 派生；`external_case` 只有显式启用时才覆盖指定参数。模型块不得保留未经登记的硬编码参数，base workspace 历史结果不得反向成为默认参数源。

为避免数据和矩阵爆炸，参数注册表增加研究优先级：

| 优先级 | 进入当前主动研究集的条件 | 当前关注内容 |
|---|---|---|
| `P0` | 直接决定电堆-BOP 守恒、接口闭合或验收门 | 电堆关键规模/负载关系、反应与热电需求、空气/氧供给、cEGR 比值与压差、关键压力/RH/温度边界 |
| `P1` | 直接影响控制行为或代表性稳态/切换瞬态 | 负载轨迹、空气目标、背压目标、加湿/冷却控制量、阀控制参数和必要的初始状态 |
| `P2` | 影响局部动态或量级但不阻断当前闭合 | 非关键容积、次要压降、未敏感的设备细节和次要数值设置 |
| `deferred` | 缺少来源、验证数据或当前研究不需要 | 效率、轴系、喘振、分离效率等尚未具备证据的能力参数 |

只有 `P0/P1` 进入当前专项的主动匹配和代表性矩阵；`P2` 只在敏感性或异常诊断需要时启用；`deferred` 只保留登记和数据需求，不扩展研究矩阵。参数数量以“能否改变当前研究结论或验收结果”为筛选依据，不以注册表完整性替代研究重点。

## 6. 当前阶段判定

Route A 已完成官方派生物理网络、cEGR/no-cEGR 单模型变体、约 `50 kW` 官方案例参数基线、反应/冷却量级账本与接口契约审计。Stage 1 的早期恒 `28 A` `0 / 0.10 / 0.30` cEGR 比矩阵保持同一 cEGR 拓扑、同一保存相位和逻辑尾窗 `[540,600)`，以尾窗均值、标准差和跨度相对同相位零目标参考做成对差分；其 `WM-L1+` 水账本直接复用同次 `SimulationOutput`，不重复启动水审计仿真。

Stage 1 已进一步完成 low/nominal/high `j=0.2/0.7/1.2 A/cm^2`、目标 cEGR `0/0.10/0.30` 的九工况恒电流、恒总压缩机流量矩阵。该主证据使用 `cegr_valve_max_area=2x` 的临时物理配置和参数一致的内存初态；全九例严格 `MaxStep=1 s` 参考数据和正式 `MaxStep=5 s` 复现数据均在最终尾窗门下通过恒流、实际 cEGR、实际 `lambda_ca_in>1`、正向阀压差、总压缩机流量、N2/O2 闭合、无吹扫污染和六例 `WM-L1+` 水账本。`1 s` 保留为严格数值参考，`5 s` 固定为高效复现协议；不把这项数值协议外推为设备标定或未审计能力。

当前可作出的结论仅限系统级工程量级闭合和控制/物理网络行为。压缩机仍是流量源/地图接口，不代表效率、轴功率或喘振裕度已经验证；阳极 lambda、purge、循环器能力，水分离效率，冷却泵的流量能力/功率，以及散热器 UA/风量仍是明确的 L2 待证能力。

### 7.4 周期运行稳态与性能统计协议（Stage 1 补充）

当前系统包含阳极氮气累积、吹扫阀逻辑、气体/水/热库存和控制器内部状态，正常工作点不应被表述为所有状态严格不变的数学静态点。对本平台，“稳态性能”定义为：在明确边界、固定初始运行相位和固定研究时长下，系统进入可解释的周期/缓慢演化运行区间后，末段统计量所代表的系统性能；吹扫导致的周期电压变化是需要记录和对齐的物理/控制事件，不是自动判定为模型失效。

1. 正常性能研究统一从一个保存的完整 `Simulink.op.ModelOperatingPoint` 启动，而不是从环境温度、环境压力和干空气等冷启动标量状态启动。当前唯一正式状态为 `v03/mode=1`，对应近似零 cEGR、`j=0.1 A/cm^2`、`I=28 A` 的运行态，并保持 cEGR 拓扑开启以支持同拓扑比较；其 metadata 必须核验 `cegrValveModeId=1` 和 `egrReferenceKind=mode1_zero_target_near_zero`。
2. 对同一研究矩阵，所有 cEGR、气体、热、湿度和压力边界案例必须使用同一初始状态、相同 `T_study`、相同末段窗口 `W_tail` 和相同统计方式。一个案例的终态不得作为下一个案例的初值。
3. 当前 Stage 1 的恒流多工况正式协议采用逻辑 `T_study=600 s`、`W_tail=[540,600) s` 和运行时 `MaxStep=5 s`。步长由 runner 的 `SimulationInput` 传入预运行与各工况，不写入通用 `.slx` solver 默认值。该时长位于当前约 `789.807 s` 的阳极吹扫周期内，且尾窗不包含下一次吹扫；变更负载或阳极控制后，必须先验证尾窗未被未对齐的吹扫事件污染，才可复用该时长。
4. `MaxStep=5 s` 的选择不以缩短研究时长换取：已完成的 `2x` 九例 `MaxStep=1 s` 结果保留为严格数值参考，九例 `5 s` 复现矩阵均通过相同控制、气体和水账本门。两批同 caseId 的最大 `|Delta P_bar|=0.00181 kW`、相对功率差 `0.00778%`，实际 cEGR、总流量和供氧结论一致。对 high 的 `0/0.10` 两例，`300/420/480 s` 均未达到相对 `600 s` 的 `0.1%` 功率等价判据，因此 `600 s` 仍是当前默认而非冷启动的替代物。
5. 每个性能 KPI 按尾窗均值报告，即 `KPI_bar = mean(KPI(t), t in W_tail)`；同时报告尾窗跨度或标准差，作为周期相位、残余缓慢演化和数值稳定性的证据。`P_stack` 尾窗跨度采用 `P_span <= max(0.05 kW, 0.005 * abs(P_bar))` 的负载自适应门；这只界定当前系统级可解释尾窗，不把正常运行表述为严格静态点。尾窗统计不通过场景约束时，不得将单点或整个轨迹末值替代为稳态性能。
6. 控制变量法采用时间对齐的成对差分：在相同逻辑时间窗内，以同初值、零实际回流的同拓扑参考为基准，报告 `Delta KPI_bar = KPI_bar(case) - KPI_bar(reference)`。运行内早期窗口与晚期窗口的直接差仅作为库存/周期演化诊断，不作为 cEGR 因果性能结论。
7. `0 -> target -> 0` 切换仍用于证明模型和控制接口具有瞬态研究能力；它的开关时间、回流、气体组分、压力和状态轨迹单独审计，不替代上述稳态性能统计。
8. 冷启动是独立研究专题。未单独立项时，不以冷启动收敛过程作为默认性能仿真的前置计算，也不将冷态初值混入正常工作性能矩阵。

### 7.4.1 正常运行初值的复用语义

`RouteA_platform_default_initial_state.mat` 是同一模型、同一已编译 mode=1 拓扑下的完整物理/控制状态 warm start，不是只适用于其生成时 `j=0.1 A/cm^2`、`I=28 A`、新鲜空气等效 `OER=3`、零目标 cEGR 的参数 profile。metadata 中这些值只记录状态来源、保存相位和已验证的基线；它们不限制后续研究工况。后续 runner 应先挂载该 operating point，再显式设置其拥有的全部场景命令：电流/电压/功率、总压缩机流量或新鲜空气等效 OER、cEGR、背压/压力、加湿/RH 与热管理/温度控制等，并给予新工况足够的过渡时间和尾窗验证。当前恒流 runner 在 `0.5 s` 前保持 metadata 的来源电流以避免状态/命令突变，随后施加 runner 指定的目标电流；该保持步骤不是初值对研究工况的约束。

因此，更换电流密度、新鲜空气等效 OER、目标 cEGR 或其他兼容控制条件时，默认复用这份初值以跳过冷启动的温度、湿度和库存建立过程，不因工况变化本身重新生成初值。只有主模型/关键物理状态结构改变、切换到 mode=0 等不同编译拓扑，或新工况在合理过渡后仍无法达到有限且可解释的状态时，才重新评估初值兼容性。

### 7.5 水管理能力分级、阴极-cEGR 可观测性与物理边界（Stage 1 补充）

本项目的 `WM-L1` 至 `WM-L3` 是水管理建模能力分级，不是 PEMFC 领域统一的保真度标准；它以水相状态、守恒控制体和可回答的工程问题定义。它也不同于本规格中的 `l2_interface`、`L2_pending` 等设备治理标签，后者只表示待证设备接口或能力，不能据此判断水管理等级。

| 等级 | 水相状态与守恒边界 | 可作出的结论 | 不可作出的结论 |
|---|---|---|---|
| `WM-L1` | 只追踪气相水蒸气及其源、汇、RH/组分和气相库存 | 加湿、蒸气质量流和湿度对系统运行的影响 | 冷凝负荷、积液、携带、排液和分离效率 |
| `WM-L1+` | 在 `WM-L1` 上加入可读回的冷凝气相移除通量；冷凝水穿过系统边界，不形成液水状态 | 气相水源/去向、局部冷凝触发与负荷、包含冷凝移除和气相库存变化的气相水账本 | 液水库存、液水携带/留存、排液流量、分离器效率和液水守恒 |
| `WM-L2` | 至少一个集总液水状态以及对应的液水迁移、携带/留存或排液支路；气相和液相共同构成控制体 | 积液和排液瞬态、支路库存释放、携带与分离器性能对气路的影响 | 流道、GDL 或 CL 内局部淹没/干涸的空间分布，除非另有局部模型 |
| `WM-L3` | 具有经验证的分布式两相状态，例如流道/GDL/CL 的液水饱和度、毛细迁移、相变及热质传递耦合 | 局部淹没/干涸、传质受限、材料和几何对水管理的影响 | 未经独立数据校核的产品级预测 |

当前 Stage 1 冻结为 `WM-L1+`。这对当前系统级 cEGR 研究足够：必须可审计水蒸气在气路中的质量流变化、气相库存、RH/饱和状态和冷凝气相移除通量，并能以实际 `mdot_cond` 或 `mdot_c` 识别过饱和导致的冷凝；不要求建立液水库存、携带或排液模型。2026-07-17 的 mode=1 v03 回归通过后，`routeA_stage1_water_ledger_from_outputs` 固定只接收同次矩阵的既有输出，Stage 1 的 `WM-L1+` 水管理子专题验收通过并收尾。只有研究目标明确需要预测积液、携水、排液或分离效率，且具备结构、参数来源和验证工况时，才另立专题升级为 `WM-L2`。

1. 当前四物种气体网络可直接从 Simscape 日志读取新鲜进气、加湿器 `Pipe (FC).MIn` 水组分、MEA 的 `H2O_produced`/`mdot_ca`/`mdot_an`、EGR/排气 `M_i`，以及全部气相容积的 `m_I_i`、Chamber `mdot_cond` 和 Pipe `mdot_c`。这些量构成气相水源、气相水去向、局部相变和系统气相库存的证据入口，不要求先新增观察块。
2. 加湿器把 RH 控制器输出经 `PS Gain=[0;0;0;1]` 接入 `Pipe (FC).MIn`；它是显式的气相水质量源，但没有解析上游液水、蒸发器或外界湿空气之间的物理分配。
3. 当前 `Constant Volume Chamber (FC)` 的 `cond_spec` 已启用，官方 `Pipe (FC)` 也会计算水的 `mdot_c`；两者均以 `tau_c` 为有限速率把过饱和水蒸气从气相移除并计入潜热，而非严格把 RH 硬钳在 100%。`mdot_cond`/`mdot_c` 因而是气相相变损失通量；`m_I_i` 是剩余气相组分库存，不是液水库存，也没有液水端口、携带支路或排液流量。
4. 对当前官方 `Pipe (FC)` 实现，`isCond` 不可被解释为关闭 `mdot_c` 相变计算；是否存在冷凝必须以日志中的实际 `mdot_c` 为准。`SeparatorOrCondensation` 则仅计算超饱和摩尔分数乘以流量的 L2 KPI，不改变气体组分、不连接冷凝质量流，也没有分离效率参数参与计算；不得把它解释为真实水分离器排液或效率。
5. 官方 MEA 源码中 `-mdot_an(H2O)` 是带符号的净膜水传输，正值为阳极到阴极、负值为阴极到阳极；当前仅可得到净传输，不能把电渗拖曳和反扩散分别作为独立观测量。
6. 因此，当前平台可以在包含排气管的完整阴极-cEGR 气相控制体上闭合水账本，并审计局部相变通量；液水库存、液水携带/留存、分离器排液与效率仍为 `unobservable`。任何新增液水物理支路、分离器或控制器逻辑均须先形成专题规格、接口契约和最小回归工况，再经用户授权改动 `.slx`。

### 7.6 六批整合后的建模前冻结

| 批次 | 已对齐内容 |
|---|---|
| 1 | 电堆核心与供氧/cEGR 联合参数匹配及接口闭合为首个专项；电堆内部结构和机理首轮保持不变 |
| 2 | 模块来源按 `official_reuse`、`equation_based`、`l2_interface`、`deferred` 分类；经验性 MATLAB Function 不作为设备物理证据 |
| 3 | `u/w/y/z` 语义冻结；端口级名称、单位、方向和可观测性在改模前只读确认 |
| 4 | `platform_default`、场景参数、派生参数和 `external_case` 分层；当前主动研究集聚焦 `P0/P1` |
| 5 | 无/有 cEGR 和切换瞬态共用同一模型、参数源和 runner；按中负载、全稳态、切换瞬态分级验证 |
| 6 | 冻结底层原则而非所有实现；允许有证据的漏洞修复、数值优化和物理增强，全部可审计、可回归、可回滚 |

六批整合冻结后，正式进入 Simulink 前仍必须完成端口级只读读回、首个专项来源/参数/接口预检、基线 Git 提交和用户对首个实施提交的单独授权。

## 8. 顶层规划的长期预期成果

完成长期路线后，Route A 应形成以下可复用成果：

1. **系统集成设计能力**：以电堆需求为核心，能够完成供氧/cEGR、供氢/阳极水管理、热管理和电气接口的参数匹配与边界设计。
2. **代表性研究能力**：在同一模型、同一参数源和同一 runner 下，稳定研究无/低/中 cEGR、低/中/高负载稳态及代表性切换瞬态。
3. **模块化演进能力**：每个设备模块都有来源、参数、接口、保真度和验证状态；发现漏洞或获得新证据时，可以局部修复或升级并回归其他子系统。
4. **参数化与复用能力**：通过优先级参数、派生关系和显式 profile 适配不同边界与设备配置，避免复制模型和参数链。
5. **标定与验证能力**：明确哪些量可以由系统级模型验证，哪些需要独立部件数据、试验数据或局部高保真模型支持，并保留适用范围和失效边界。

### 8.1 阶段成果映射

| 阶段 | 必须形成的系统能力 | 不应提前宣称的内容 |
|---|---|---|
| Stage 1 | 电堆-供氧/cEGR 的反应、流量、组分、压力、湿度、热量和控制接口闭合 | 压缩机效率/轴功率/喘振、中冷换热或分离效率等无证据能力 |
| Stage 2 | 电堆热负荷、冷却回路、堆温控制和环境换热的能力匹配 | 无泵特性、UA、风量数据时的真实散热能力 |
| Stage 3 | 氢耗、供氢压力、阳极回流、排氮、液水和 purge 的接口与证据边界 | 未观测的阳极 lambda、循环器或分离器性能 |
| Stage 4 | 电堆输出、受控负载、必要时 DCDC/辅电的功率边界 | 与研究问题无关的完整电气系统能力 |
| Stage 5 | 可复用 profile、参数敏感性、标定/验证边界和失效工况 | 用低误差拟合替代物理依据或扩大适用范围 |

上述成果是后续专项的长期评价目标；当前 50 kW 官方案例是参考尺度和验证锚点，不是长期规划的唯一规模对象。
