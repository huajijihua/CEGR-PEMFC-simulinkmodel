## 1. 定义

Route A 是一个面向通用燃料电池系统集成设计与参数匹配的模块化平台。当前以官方 Gas Mixture PEMFC 案例提供的约 50 kW 数据作为参考尺度和验证载体，因为该案例参数相对完整且来源明确；50 kW 不是平台的最终规模限制。平台以单一 Simulink/Simscape 物理网络为核心，通过参数层和编译期 cEGR 变体覆盖无 cEGR 与有 cEGR 工况，并保留按边界参数和设备参数重新配置的能力。

本模型用于研究电堆与供氧、供氢、热管理、受控负载接口之间的物理耦合、参数匹配和控制约束。它当前是系统级物理网络和集成设计平台，不承担三维机械装配或完整高压电气系统的建模责任。

### 1.1 建模保真度与系统级边界

Route A 的设备模块保真度按以下来源优先级确定：

1. 优先复用官方燃料电池系统案例、官方 FuelCell/Simscape 物理网络和可复用的 Simulink/Simscape 模块；模块级复用必须保持原有物理端口、守恒关系和参数语义。
2. 官方资产未覆盖的设备责任，必须以可追溯文献或明确的物理化学原理方程为基础，包括质量、动量、能量、组分、相平衡和电化学关系等。
3. 只有工程量级假设或缺少来源的数据，保留为参数占位、边界条件或 L2 待证接口；不得据此宣称设备机理、效率或能力已经建立。
4. MATLAB Function 可用于控制逻辑、状态机、代数换算、参数装配和 KPI 计算，但不得以未经验证的经验公式作为设备物理模块的唯一基础。

Route A 是复杂的零维集总参数系统级模型。“零维”只限定空间分布建模边界，不代表模型简单，也不降低对物理机理和系统耦合的要求。模型由电堆机理、气体/水/热/电多域网络、BOP 设备、控制器、守恒与本构关系、动态状态以及参数匹配关系共同组成，并通过常微分/代数关系、必要的微分代数求解、Simscape 物理端口和信号变量传递实现耦合。模型以第一性原理、守恒定律和可追溯机理方程为主要依据，不在 Route A 内求解几何结构、空间分布或偏微分方程场；需要空间场分布时，再由独立高保真工具承担局部校核，不改变 Route A 的系统级定位。

## 2. 工程化目标

1. 建立可复用的燃料电池系统集成设计方法：以电堆为核心，完成供氧、供氢、热管理和电气接口之间的设备选型、连接关系、能力匹配和控制边界设计。
2. 基于可追溯的物理网络和参数来源，计算功率、物质、压力、温度、湿度与热负荷的系统级响应；当前用官方约 50 kW 案例作为基准工况和量级锚点。
3. 由电堆功率和反应需求推导 BOP 的流量、压力、热管理和控制能力要求，而不是孤立调整模块参数。
4. 维持一套模型、一个 `platform_default` 参数源和一个全工况研究入口；外部设备或边界数据只能经显式 profile 或 `external_case` 接入。
5. 允许以不破坏系统接口的方式，将 L2 设备接口逐步替换为经过参数匹配或标定的部件模型，并支持未来更换电堆规模或设备配置。

## 3. 系统边界与架构

| 工程域 | 当前模型责任边界 | 当前保真度定位 |
|---|---|---|
| 电堆核心 | MEA、阴阳极气道、出口容腔、堆热和电气端口 | 官方物理网络内核 |
| 供氧与 cEGR | 空气源、压缩机/地图、入口混合、中冷接口、阴极加湿、回流阀/管、排气、背压和阴极水管理接口 | 官方物理网络加 L2 设备接口 |
| 供氢 | 储氢、减压、阳极加湿、回流、排氮与阳极水管理接口 | 官方主结构加 L2 回流/分离接口 |
| 热管理 | 冷却通道、泵、散热器、环境换热和控制接口 | 官方热液网络，待做能力匹配与控制闭合 |
| 电气 | 受控负载、电流/电压/功率测量 | 系统边界接口；不在当前阶段建立 DCDC、母线和辅电架构 |
| 控制与观测 | 空气、cEGR、背压、湿度、冷却接口以及 KPI | 研究级控制接口；不承担完整系统控制软件 |

cEGR 是供氧/阴极排气水管理域的一条可切换物理支路，不是并行的第五套 BOP。无 cEGR 通过 `cEGR_Mode_Selector` 的官方无限流阻隔离实现；有 cEGR 保留排气、水分离、阀、回流管和入口混合链。

### 3.1 工程化目标设备与当前替换边界（草案）

| 工程域 | 目标设备与物理责任 | 当前 Route A 定位 | 升级前提 |
|---|---|---|---|
| 供氧与 cEGR | 空压机、中冷器、加湿器、节气门/背压、cEGR 阀与管路、水分离、流量/P/T/组分传感器；负责新鲜空气、回流尾气和水热状态的守恒与控制 | 官方四物种网络、压缩机流量源/地图、回流物理支路和 L2 中冷/分离接口已存在；不宣称机械效率、轴功率、喘振、中冷或分离能力已验证 | 需要设备地图/效率、压降、换热或分离数据，以及独立验证工况 |
| 供氢与阳极水管理 | 储氢/减压、比例阀或喷射器、循环泵或引射器、分离器、purge 阀和 P/T/流量传感器；负责氢供给、回流、惰性气体与液水管理 | 官方阳极主结构和 L2 回流/分离接口保留；不宣称阳极 lambda、purge 或循环能力闭合 | 需要供氢压力-流量、循环器/引射器和排氮/分离证据 |
| 热管理 | 冷却通道、冷却泵、电子节温器、散热器、环境换热，以及必要时 PTC；负责反应热移除和堆温约束 | 官方热液网络、温度控制接口和散热器几何接口保留；泵能力、UA、风量和 PTC 均待证 | 需要泵特性、冷却回路压降、UA/风量与热平衡数据 |
| 电气接口 | 受控负载、堆电压/电流/功率测量、后续 DCDC、母线和辅电边界 | 当前仅承担受控负载和测量；DCDC、母线与辅电不在本阶段实现 | 仅当研究问题需要系统供电或车辆能量管理时引入 |

上述表是目标设备目录和复用边界，不是新增模块清单。L2 接口表示系统级边界或待替换占位，不等同于经验性等效设备模型。任何设备只有在官方模块复用或物理方程、参数来源、接口语义和验证证据齐备后，才可替换对应 L2 接口；替换时必须保持单一主模型和既有 `u/w/y/z` 契约。

## 4. 接口原则

| 类别 | 当前或后续接口 |
|---|---|
| 控制输入 `u` | 功率请求、空气模式与 OER/质量流量目标、cEGR 模式与目标比值、阴极出口压力目标、加湿器与冷却控制量 |
| 外界输入 `w` | 环境压力/温度/RH、氢源状态和组分、初始状态以及用户定义的边界参数 |
| 控制测量 `y` | 电流、电压、功率、压缩机入口流量、cEGR 流量/比值、阴极出口压力、RH、温度、冷却相关测量 |
| 审计真值 `z` | 实际入堆氧质量流和 `lambda_ca_in`、内部组分、热量、分离水 KPI、执行器饱和与物理节点状态 |

控制命令不能代替物理验收。特别是 OER 命令不能代替实际氧供给，cEGR 评价必须以混合气组分、实际氧计量比和压力链为准。

`routeA_cegr_enabled` 是仅在独立仿真前 `update diagram` 生效的编译期变体，禁止在单次连续仿真中切换。无 cEGR case 同时要求该变体关闭且目标回流比为零；有 cEGR case 的阀面积、阀前后压力和实际回流比均只作为 `z` 审计量，不反馈修改现有控制律。连续 Simscape 物理量按 variable-step 处理。

已完成的参数匹配与接口契约审计只在 base workspace 生成 `routeA_phase1_audit`。其包含反应/冷却账本、参数注册表、接口契约、被动 cEGR 诊断和缺口表；不导出 CSV、图片、模型副本或缓存。若当前 base workspace 已有同一模型、同一 9 工况矩阵定义的完整结果，审计入口复用该结果，只补充两条被动 cEGR 诊断。

## 5. 保真度与参数规则

1. 官方 `FuelCell_lib`、官方案例和官方系统级模块直接覆盖的物理内容优先复用，并优先采用模块级复用而不是重新编写等效模块。
2. 官方资产未覆盖的内容，必须以可追溯文献或明确物理化学方程搭建；方程、状态量、边界条件和适用范围必须能够单独审计。
3. 中冷器、水分离器、压缩机机械动态、氢循环装置、加湿器水热传递、节温与 PTC 等未充分实现内容必须标明为 L2 接口、待升级设备或待标定模块，不得用经验性 MATLAB Function 公式补齐并冒充设备机理。
4. MATLAB Function 仅用于控制、逻辑、代数换算、参数装配和诊断计算；若其承担设备物理责任，必须有独立方程和来源证据，不能仅凭脚本无报错或曲线拟合成立。
5. 每项可调参数后续必须归入机理参数、设备能力参数、控制参数或数值参数，并记录单位、来源、适用范围和验证状态。
6. 不以数值收敛替代工程真实性；也不因暂缺设备数据而提前建立无法验证的高保真动态。

### 5.1 证据等级与复用边界

1. “已验证事实”仅限模型读回、官方来源、已完成的当前 runner 验收或独立数据直接支持的结论。
2. “基于证据推断”可用于提出量级、架构或升级优先级，但不得写成部件能力、效率或系统/设备性能。
3. “待确认假设”必须保留为 `deferred`，并在进入任何专项前转化为明确的数据需求或验证任务。
4. 外部配置只能通过 profile 或 `external_case` 接入；参数拟合需单独记录训练/验证边界、适用范围、误差和失效工况。

## 6. 当前阶段判定

Route A 已完成官方派生物理网络、cEGR/no-cEGR 单模型变体、50 kW 平台参数基线、九个稳态全工况功能性验证，以及反应/冷却量级账本与接口契约审计。无 cEGR 回流严格为零；0.10/0.30 cEGR 的回流跟踪、实际入堆氧计量比和尾段功率稳定性均通过现行门槛。名义负载下的被动阀诊断确认两种 cEGR 目标均具有正向阀前后压差，且阀面积未触及上限。

当前可作出的结论仅限系统级工程量级闭合和控制/物理网络行为。压缩机仍是流量源/地图接口，不代表效率、轴功率或喘振裕度已经验证；阳极 lambda、purge、循环器能力，水分离效率，冷却泵的流量能力/功率，以及散热器 UA/风量仍是明确的 L2 待证能力。

当前尚未完成：真实空压机效率/轴系与喘振边界、真实中冷/加湿/水分离能力、氢循环器或引射器、阳极 purge/lambda 闭环、完整热管理控制、DCDC/辅电架构、参数标定和独立验证。

## 7. Phase 4 待共同确认的顶层决策

1. 研究问题优先级：以通用燃料电池系统集成设计与参数匹配为总目标，再确定 cEGR 机理/性能、BOP 匹配、设备参数化和验证工作的先后关系。
2. 研究场景范围：无/低/中 cEGR 下的低/中/高负载代表性稳态，以及一次“无 cEGR-开 cEGR-无 cEGR”的代表性切换瞬态；完整边界参数和设备参数的可调性属于系统能力，不要求穷举全部组合。
3. 设备保真度与建模来源：四个工程域中首个允许升级的设备；优先采用官方案例/官方模块级复用，其次采用文献或明确物理化学方程；允许的 L2 简化、禁止的经验性 MATLAB Function 等效模块和必须保持的物理网络。
4. 可用证据：部件数据表、试验数据、工况边界和可用于独立验证的 KPI。
5. 标定与验证目标：参数拟合的对象、训练/验证划分、可接受误差和必须满足的物理门槛。
6. 专项执行顺序：每项的隔离边界、允许/禁止改动、最小回归和退出条件。

### 7.1 后续专项演进顺序（规划建议）

| 顺序 | 专项 | 选择依据 | 当前边界 |
|---|---|---|---|
| 1 | 供氧与 cEGR 参数匹配及接口闭合 | 当前 Route A 已有官方气体物理网络、cEGR 支路、控制链和稳态证据；其流量、组分、压力、湿度和回流比直接决定系统级研究能力 | 先审计来源、参数、能力账本和接口，不新增经验性设备等效模块 |
| 2 | 热管理参数匹配与热控制闭合 | 反应热、冷却需求和堆温是跨域约束，需在供氧边界稳定后闭合 | 保持现有热液网络；无泵特性、UA 或风量证据时保留 L2 |
| 3 | 供氢与阳极水管理参数匹配 | 氢供给、回流、排氮和液水管理是系统闭合的另一条物质链，但当前可观测与部件证据较少 | 先定义接口和证据需求，不宣称阳极 lambda、purge 或循环能力已验证 |
| 4 | 电气接口与辅电边界 | 只有当研究问题需要系统供电、DCDC 或辅电耦合时才提升优先级 | 当前维持受控负载和电流/电压/功率测量，不提前建立电气设备模型 |

该顺序是 Phase 4 的规划建议，不是 `.slx` 改动授权。每个专项必须在前一专项的接口和验证门通过后单独立项。

### 7.2 首个专项：供氧与 cEGR 参数匹配及接口闭合

**目标**：在不改变主模型结构、默认参数、控制律和全工况入口的前提下，闭合电堆与供氧/cEGR 域之间的流量、组分、压力、湿度、回流和控制接口，明确每个模块的来源等级、能力边界和待证缺口。

**审计对象**：官方气体混合电堆网络、空气源与压缩机流量源/地图接口、中冷接口、阴极加湿、cEGR 阀与回流管、排气/背压、水分离、入口混合、流量/P/T/RH/组分测量和现有空气/cEGR 控制链。

**允许内容**：

- 读回模块来源、物理端口、参数引用、单位和当前 `platform_default` 链。
- 建立电堆反应需求到新鲜空气、回流量、压力、湿度和热负荷的能力账本。
- 对目标回流比、实际回流比、阀面积、阀前后压差、入口氧计量比和执行器饱和形成证据链。
- 标出官方复用、方程支撑、L2 接口、待证数据和 `deferred` 项，不用经验性 MATLAB Function 补齐缺口。

**禁止内容**：修改 `.slx` 结构、重写现有控制器、修改 `platform_default`、新增设备等效模块、把控制命令当作设备能力证明、引入空间场模型，或在没有来源数据时宣称压缩机效率/轴功率/喘振、中冷换热或分离效率已经验证。

**所需证据**：官方案例和模块路径、物种与守恒方程、压缩机流量/压比地图及有效范围、管路和阀压降/流通特性、加湿与水分离能力数据、传感器语义、代表性稳态矩阵和 `0 -> representative -> 0` 切换瞬态的 KPI 定义。

**最小验收**：所有审计对象有来源和状态；流量、组分、压力、RH、`lambda_ca_in` 和 cEGR 比值计算有限且量纲正确；无 cEGR 回流为零；低/中 cEGR 目标跟踪、压差方向和阀面积边界正确；请求流量与压缩机地图范围一致；缺少部件能力数据的项目明确标为待证。

**隔离与退出**：冻结电堆、供氢、热管理和电气接口，只读取其边界需求，不因本专项修改其他域。专项完成的退出条件是形成来源/参数/接口/缺口闭合表，并由用户单独确认后才可进入最小 Simulink 改动或参数专项。
