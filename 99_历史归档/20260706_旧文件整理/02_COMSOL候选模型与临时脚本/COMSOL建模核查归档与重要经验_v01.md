# COMSOL建模核查归档与重要经验_v01

本文档聚焦本项目 COMSOL 燃料电池模型建模、重建、核查和互审过程中的专项经验。重点不是回放每个步骤，而是沉淀后续做二维燃料电池模型时必须优先检查的对象、常见误区和推荐工作流。

## 1. 本轮 COMSOL 任务的关键结论

### 1.1 已确认可行的路线

- 纯 Python/mph 可稳定连接 COMSOL Server 会话并做只读/受控修改
- 通过从源 `.mph` 插入 `func + comp1`，可把参数、几何、材料、变量和基础物理场带入目标空模型会话
- `exp_*` 函数作为模型内函数链的一部分，可以保留

### 1.2 已确认不应再走的路线

- 不再给模型挂接外部临时 CSV
- 不再把 `.codex_temp/case_*.csv` 当作 COMSOL 模型正式数据源
- 在用户未要求 MATLAB 的纯 COMSOL 任务中，不切换到 MATLAB LiveLink

### 1.3 当前能力边界

截至本轮验证：

- 对“从已有源模型插入组件结构”的 Python/mph 路线，已验证可靠
- 对“完全不依赖源模型，仅用 Python/mph 从零稳定创建带正确空间维度并可直接创建复杂物理场的 component”，尚未完成闭环验证

这意味着：

- 若已有可靠源模型，优先采用“插入组件结构”路线
- 若无源模型，且任务要求纯 Python 从零建模，则应把“component/geometry/physics 初始化机制验证”视作单独任务，而不是默认可稳妥完成的步骤

## 2. COMSOL 工作流经验

### 2.1 先做结构 inventory，再决定是否修改

对于已有 `.mph` 会话，建议先只读抓取：

- model name / file
- component tags
- geometry tags + `sdim`
- geometry feature tags
- physics tags + interface type
- variable group tags + entry count
- material tags
- function tags
- study / solver tags
- external file references

这样可以先判断：

- 模型主干是否完整
- 是否是 2D / 3D / 错维度
- 是否已有物理场
- 是否存在危险外部依赖

### 2.2 先区分主干资产与 COMSOL 自动派生对象

建议把模型对象分成两层：

主干资产：

- 参数
- 用户命名变量组（如 `var75/var74/var76/var77`）
- 用户定义函数（如 `exp_*`、`pw1`、`an1`）
- 组件、几何、材料、物理场
- 核心 study / solver

自动派生对象：

- `iexpr*`
- 大量 derived variables
- 材料、求解器和多物理场自动生成的内部变量

原则：

- 主干资产用于回答“模型是否搭对”
- 自动派生对象用于回答“模型是否干净/是否存在异常膨胀”

### 2.3 域/边界核查要区分 FC 模块自动过滤与显式选择对象

本轮一个重要纠偏是：不能把 UI 上显示的“所有域”直接判定为建模错误。

对于 COMSOL Fuel Cell 模块中的这类相/子特征：

- `icph1`
- `h2gasph1`
- `o2gasph1`

即使界面显示为“所有域”，COMSOL 也会按物理适用性自动过滤不允许的域；不适用的域会在界面中标注为“不适用”，不会被真正纳入求解。
因此，**仅凭它们显示为“所有域”不能得出“域选择过宽导致物理错误”的结论。**

但这不意味着域/边界核查可以省略。更严谨的口径应当是：

- 对 FC 模块的相定义、膜、电极、流道等特征，要区分“UI 选择状态”和“实际适用域”
- 对 Brinkman、入口/出口、显式多孔介质、边界条件等非自动过滤对象，仍应重点核查真实域/边界分配
- 物理正确性最终仍要回到 KPI 与参考工况，而不是只看树节点显示文本

固定结论：

- 对 FC 模块，表面显示“所有域”不是充分错误证据
- 对显式域/边界控制对象，错误分配仍然可能造成明显物理偏差
- 对燃料电池模型来说，域/边界核查依然是主检查项，但核查方法必须尊重 COMSOL 的自动过滤机制

### 2.4 收敛只是数值信号，不是物理正确性证明

应至少补一个参考工况核查，例如：

- `V_cell`
- `dp_c`
- `dp_a`
- `T_stack` / `T_cool_out`

若参考工况偏差很大，应优先回查：

- 边界条件
- FC 模块相定义的真实适用域与物理语义
- Brinkman 与多孔介质显式域设置
- 薄扩散电极动力学参数

而不是先怀疑 solver 本身。

## 3. 本轮识别出的具体风险类型

### 3.1 外部文件依赖风险

高风险信号：

- 函数节点 `filename/sourcefile` 指向 `.codex_temp`
- 引用了 `case_*.csv`
- 表格列数与模型期望列数不一致

处理原则：

- 首先查 `Global Definitions -> Functions`
- 再查 `Component -> Definitions -> Functions`
- 再查 `Interpolation/Table/Import`
- 一旦发现临时路径，不应继续围绕该路径修补，而应恢复到模型内部函数体系或原始合法数据源

### 3.2 结构污染风险

高风险信号：

- 大量 `iexpr*`
- solver 链过长且缺少解释
- 用户主变量组被自动派生对象淹没

这类问题不一定立即阻止计算，但会显著增加：

- 排障成本
- 交接成本
- 后续增量修改风险

### 3.3 默认动力学参数风险

如果薄扩散电极、反应层、交换电流密度等关键对象仅依赖默认值，模型可能：

- 能运行
- 但物理偏差较大

建议核查：

- `i0ref`
- `Av`
- `alpha`
- GDE / CL 厚度

是否明确设置，而非完全依赖默认值。

## 4. 推荐核查顺序

后续做燃料电池 COMSOL 模型核查，建议固定顺序如下：

1. 结构层
   - component / geom / physics / materials / variables / functions / studies / solvers
2. 依赖层
   - filename / sourcefile / external import
3. 选择层
   - 边界选择
   - Brinkman / 多孔介质等显式域设置
   - FC 模块相定义的实际适用域
4. 物理层
   - 参考工况 KPI
5. 洁净度层
   - `iexpr*`
   - solver 冗余
   - 自动派生节点是否异常膨胀

## 5. 对后续建模任务的建议

### 5.1 如果用户先给几何模型

这是更稳的路线。Agent 更适合接管：

- 参数设置
- 变量组织
- 函数体系
- 物理场接口
- 域选择 / 边界条件
- study / solver
- 只读回检

### 5.2 如果已有可靠源模型

优先路线：

- 插入源组件与函数
- 再做针对性精简和校验

不优先路线：

- 从零纯手搓整个多物理场结构

### 5.3 如果要做跨 Agent 协作

建议分工：

- 一方先做结构搭建与依赖核查
- 另一方重点做 KPI、物理语义、边界条件和显式域设置复核

避免两边都把精力耗在大量内部派生对象枚举上。

## 6. 本轮已确认的一个重要纠偏

需要明确记录：

- `icph1` / `h2gasph1` / `o2gasph1` 在界面中显示“所有域”，本身**不是错误**
- COMSOL 会自动识别允许域，并把不适用的域标记为“不适用”
- 后续审计时，不能再把这类 UI 显示直接等同于“域选择过宽”

真正需要警惕的是：

- 外部错误依赖
- 显式多孔介质/边界条件错配
- 关键 KPI 偏离合理范围
- 重要动力学参数依赖默认值但未说明

## 7. 本文件的定位

本文件属于 COMSOL 专项归档，后续应随着模型演进持续补充：

- 已验证可行的构建路线
- 已识别失败模式
- 关键 feature 的核查口径
- 参考工况 KPI 包络
